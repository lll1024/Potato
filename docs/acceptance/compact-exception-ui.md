# 对话异常紧凑展示验收

设计依据：[已确认设计](../design/model-request-failure-ui.md)。基准提交：`d0de25e9301ff465f34b2e26031ce0be35e97fcf`。

## 行为变化

- 异常状态在对应用户消息下方显示圆形重试图标与一句短提示，去掉大段应用说明、资料空态及空助手回复块。
- 模型短提示使用最终请求的既有错误分类；认证、额度、限流、超时、连接、服务错误、空响应和上下文超限分别表达。旧错误不会覆盖最终原因，未知分类使用“请求失败”。
- 自动重试只显示真实进度，详细重试历史留在执行轨迹。主动停止、查询或输出上限、地图暂停、服务中断和存储故障保持各自含义。
- 仅最新且符合条件的异常轮次可重试；仍以原需求创建新轮次，保留输入框草稿，重复点击不重复提交。历史异常提示保留。
- 已有资料与完整错误通过本轮轨迹查看；部分模型回答保留并标注“回答不完整”，空正文不生成助手块。

## 测试先失败再通过

1. 浏览器新增紧凑异常提示用例：旧实现找不到“第 1 轮异常提示”区域；实现后通过。
2. 公开 HTTP 验证额度失败分类：旧快照缺少 `model_error_code`，触发 `KeyError`；从最终错误载荷取得分类后通过。
3. 浏览器验证分类短提示：旧展示对认证错误返回“请求失败”；映射后显示“模型认证失败”，其余已知分类及未知分类也通过。
4. 重试期间仅显示简短进度：旧聊天区仍有“模型重试记录”；将详情保留在轨迹后通过。
5. 输出上限后空正文：初版仍渲染“旅行助手”空区域；检查非空正文后通过。
6. 双轴审查指出独立的上下文超限与恢复不可用终态未分类：新增两项界面测试均先误显“请求失败”；补齐短提示后，整个异常测试文件通过。

## 全量浏览器回归的既有失败

`context-compaction-live.spec.ts` 的 1440px、390px 两项用例均在第一次提交后等待固定模型回答时失败。以该测试相同的输入和启动器，通过公开 HTTP 分别在未修改的基准提交与本次工作区独立复现，结果一致：

| 检查 | 未修改基准 | 本次工作区 |
| --- | --- | --- |
| 输入估算 | 28,153 tokens | 28,153 tokens |
| 安全输入预算 | 28,000 tokens | 28,000 tokens |
| 实际模型请求次数 | 0 | 0 |
| 轮次终态 | terminated / context_budget | terminated / context_budget |

夹具的首次当前输入已超过预算，系统按既有规则阻止请求，因而不会出现测试等待的回答。本次保留原测试与上下文预算规则，不将这两项报告为通过。
