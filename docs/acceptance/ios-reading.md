## 交付行为

会话列表和对话均可继续加载后端完整内容。列表游标原样传回；按身份去重，刷新重新核对已展开的页数，使电脑端改名、删除和新内容得到更新。列表刷新与继续加载依次读取，全局快照仍先独立核对；慢分页不会因普通轮询反复失效，刷新也不会被正常翻页误标为断线。

历史保留每个轮次的读取事件位置，按身份去重及后端 ordinal 排序；旧响应不能覆盖更新的完成事实。实际读取的连续区间保留后端继续入口，新增内容跨过多页时，优先补齐新旧范围之间的缺口；迟到旧页不能关闭这个入口。切换服务、数据集和会话使旧分页目标失效。失败保留最后已读内容与继续入口，404 明确显示会话不存在。历史只在当前共享内存投影中合并，不向手机 GRDB 同步历史。

继续加载经 View → Presenter → Interactor → SessionAccess，Router 仍负责进入与返回。对话支持查看更早位置及回到最新，加载旧页保留原阅读锚点。手机没有增加搜索、改名或删除管理入口。

`AnswerView` 封装 MarkdownUI，显示完整 Markdown、中文标题与列表，支持文字选择、系统浏览器打开链接及复制完整原文。宽表格在独立横向滚动区域展示，列宽随 Dynamic Type 缩放。复制保留 Markdown 标记和全文。预约入口样例明确说明尚未预约，不发起预订或付款。

## Standards

累计 3 项 P2：首轮列表刷新在正常翻页完成后可能把过期读取误报为断线；新增公开分页入口的契约尚未同步。已通过公开回归复现并改为列表依次读取，过期读取不修改连接；公开契约同步分页、合并、失效及失败语义。复核发现的 View 直接更新观察目标也已改为经 Presenter → Interactor。最终复核 0 项遗留、0 项新增。

## Spec

首轮 2 项 P2：第一页完全不变时，迟到第二页可能带回电脑端已删除会话；正常翻页成功可能触发虚假断线。前者通过列表读取串行化及刷新已展开页数解决，后者与 Standards 的竞争修复共同验证。另补充旧页 404 与更早历史成功响应的删除竞争，避免恢复失效事实。最终复核 0 项遗留、0 项新增。

## 演示步骤

1. 按 [iOS README](../../ios/README.md) 启动六个真实 HTTPS 测试服务，模拟器配置 `https://localhost:18495`。
2. 在列表底部加载更早会话，能看到「阅读样例会话 01」；返回顶部打开「杭州两日旅行阅读验收第1轮」。
3. 点击工具栏「查看更早对话」，加载旧页后向上查看第 1 轮完整输入；表格在自身区域左右滑动。
4. 点击「回到最新」，复制完整回答并粘贴至输入框核对，保留两日安排、表格、链接与全文结尾；不要发送复制材料。
5. 打开「查看预约说明」，系统浏览器显示预约入口样例及尚未预约说明，再回到 App；通过系统返回回到同一会话列表。
