## Spec

1. **[P1] 历史回指触发错误改期**（`travel_dates.py:84–97`）。#30：“历史输入的相对表达不按新时间重新解释。”公开 HTTP＋重启复现：10/9“明天去杭州西湖”保存10/10；10/10“之前定的明天去杭州西湖安排不变，只换午餐餐馆”保存10/11且 `dates_changed=true`。正则把“明天去”当成新出行，导致天气和官方资料核对错误日期。

2. **[P1] 公历日期被误当旅行天数**（`travel_dates.py:16,41–43`）。#28：“显式日期及用户明确修改优先。”输入“2026年10月10日游览故宫”，HTTP 保存10/10–10/19；`10日游` 被识别为十日游，凭空扩大日期范围。

3. **[P2] 澄清答复无法解除旧冲突**（`travel_dates.py:94–97`）。#28：“确有天数冲突或歧义时才澄清。”周日“本周末去北京两日游”后答“那改成一日游”，HTTP 仍保存旧 `needs_clarification` 和“两日要求冲突”。已解决的冲突继续作为权威上下文要求模型追问。

4. **[P2] 修改天数未更新日期范围**（`travel_dates.py:74–97`）。#28：“显式日期及用户明确修改优先”；#30：“更新受影响的安排、天气适用性和后续查询条件。”首轮确定10/10，续聊“改成两日游，起始日期不变”，HTTP 仍保存仅10/10，缺少10/11与改期标记，异常天气摘要也遗漏新增日期。

5. **[P2] 未读小程序仍编造界面流程**（`agent.py:175`，实际回答 `real-official-first-v4.log:61`）。#32：“按证据实际强度说明待核实事项”；#28：“动态页面、公众号或小程序无法读取时采用同样策略。”真实模型回答列出“进入票务/展览预约模块→选择…→完成核验”，官方须知只证明指定小程序实名预约，小程序界面未读。当前提示存在但实际验收未满足；需收紧并真实复验。
