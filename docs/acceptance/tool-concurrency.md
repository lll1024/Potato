# 网页十并发与服务故障隔离验收（#75）

2026-10-13，功能分支 `codex/shared-call-budget`，本任务起点 `f0aeaaaefa7f02a07a39608ca989cace0c410927`。范围为 [Issue #75](https://github.com/lll1024/Potato/issues/75)，父规格 [#73](https://github.com/lll1024/Potato/issues/73)；复用 #74 的功能分支和 PR #77。

## 实现行为

每次模型响应提出的外部查询按提出顺序预留本轮工具余额，地图内部最多一个在途请求，网页搜索与正文读取合计最多十个。单个多链接正文工具仍占一次名额及一次预算。地图和网页名额独立，两侧可以重叠；分别保留 0.4 秒启动间隔，网页启动锁在实际请求前释放，不等待该请求返回。

每项任务固定原身份、参数、记录归属及观察回调，状态和结果逐项提交，公开快照和 SSE 随真实进度更新。查询可以乱序返回，列表与最终工具结果保持模型提出顺序；整批收齐前不发出下一次模型请求。历史搜索／回读作为串行边界，先收齐前段外部结果，再使用真实结果、后续协议占位和上下文余量读取；已收齐结果的协议引用也可在同批历史边界回读。历史八次、分页、字符及会话权限限制保留。

供应商故障只暂停对应服务，地图连接故障不再退出 CLI 或停止整个 Web 服务。模型下一次请求获得实际暂停状态，双家故障也不错误宣称另一服务可用。普通参数／业务错误及既有可恢复失败继续按原分类处理；不新增相同工具请求的自动重试、供应商切换、注册或付费。

用户停止、真实服务退出或状态／结果保存失败阻止后续调用。已发出的多个请求继续等待实际返回、错误或自身超时，并逐条尝试保存；批次收齐后才传播保存异常，全局名额不提前释放。未保存结果保持最后可靠事实，重启将未完成轮次标记中断且不重放。128 次工具及 64 次实际模型请求、一次无工具最终回答预留仍按 #74 执行。

## 公开边界证据

主要测试 [test_tool_concurrency.py](../../tests/test_tool_concurrency.py) 通过公开 `/api/turns`、HTTP／SSE、载荷、快照及重启回读运行真实循环、MCP／HTTP 适配器和 SQLite。只替换外部模型及供应商响应，使用请求阻塞／逐条释放观察在途数量，不用偶然的耗时变化代替重叠证明。

| 场景 | 验证行为 |
| --- | --- |
| 12 个混合网页请求、3 个地图请求 | 阻塞时地图 1 条、网页 10 条同时在途；释放一个网页名额后第 11 条才启动；地图按提出顺序推进，两侧实际启动间隔均保留 |
| 网页乱序完成 | 第 8 项先完成时公开状态及时可见，其他仍运行；下一模型请求尚未发出，最终身份、参数及结果顺序逐项对应 |
| 历史串行边界 | 前段地图未返回时历史与后段网页不启动；前段收齐后回读真实网页原文及来源、历史核实状态，再继续后段查询 |
| 单家或双家故障 | 地图鉴权、额度、服务、真实 HTTP 连接错误及网页限流、连接错误隔离；已发出请求保存真实成功结果，暂停服务的等待任务不调用，下一轮可继续可用服务 |
| 双家暂停后的网页结构化额度错误 | 修复前结果错误声称地图可用；修复后保留准确状态，无失败资料进入查询资料事实 |
| 并发名额与启动间隔中停止 | 新请求不启动，已发出调用保存真实返回；收束前新轮提交仍拒绝，旧停止身份不影响新轮次 |
| 真实 Web 服务退出 | 多个请求在途时关闭服务器，等待真实返回后退出；重启保留 `service_shutdown`、已完成结果与未执行原因，不自动发出模型请求 |
| 单条结果保存失败 | 首个异常停止派发，但其余在途调用继续返回并成功保存；失败结果没有结果载荷，名额保留至收齐，重启保留可靠结果及中断限制 |
| 启动状态保存失败 | 未进入 SDK 的任务保持已保存等待事实；此前两侧在途调用仍收束并保存，无后续模型请求 |
| 128 次预算与乱序完成 | 按提出顺序执行 127 个网页加 1 个地图；失败也扣账，后面的网页和地图均未执行；较早请求未返回时不发最终模型请求，收齐后无工具收尾 |
| SSE 与浏览器 | 部分结果完成时 SSE 立即可见；桌面／手机的工具行保持提出顺序，完成、执行和等待标签准确；已有时间线使用真实时间保持重叠 |
| CLI 与既有回归 | 地图断连后继续接收输入，退出时关闭资源；共享预算、历史权限、上下文、重试、停止、存储及真实进程恢复回归保留 |
