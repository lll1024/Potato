## 交付与验收对应

| 验收范围 | 实现及证据 |
| --- | --- |
| 公开能力与有序外部段 | `Retrieval.capabilities` 返回能力声明副本与真实状态，`execute(list[Query])` 按输入身份、长度和顺序返回不可变结果；供应商对象、锁和内容处理均在 retrieval 内部 |
| 调度与故障隔离 | 保留地图按提出顺序串行、搜索与正文最多十个在途、两类重叠及各 0.4 秒启动间隔；严重故障只暂停对应能力，公开网页发现失败保留地图 |
| 资料表达兼容 | 工具名称、参数、成功／失败／未启动、来源、摘录与正文、查询时间、核实和预订边界保持；普通资料不升级为已核实旅行信息 |
| 混合批次 | planning/batch.py 唯一持有分段、屏障和结果拼接；前段真实结果全部收齐后回读历史，按完整请求余量及后段占位分页，再一次性交回完整有序结果 |
| 整轮预算 | planning/budget.py 拥有 128 次工具总账和 64 次实际模型请求；历史局部 8 次上限、逻辑步骤及实际请求分开；重试、摘要、恢复共享实际总账，保留最后一次无工具回答 |
| 收尾与真实终态 | 预算耗尽先等在途；最终请求不再查询、摘要或重试；停止、容量不足、最终失败与记录故障保留已有资料，不伪报旅行规划完成 |
| 保存故障 | 开始事实未保存不进入服务；结果事实失败停止新启，但先等待其他真实返回与全部保存尝试；不提前释放会话名额 |
| 共同模型事实 | model_execution.py 仅采集实际 SDK 返回、错误、用量及脱敏内容；普通重试和摘要局部策略保持独立，不增加多供应商框架 |
| 真实调用与边界 | 当前 Web 与 CLI 只装配公开规划／查询资源；移除七个旧生产文件，新增代码立即接受模块边界检查，retrieval 与 context 无相互依赖 |

公开契约：[资料获取](../modules/retrieval.md)、[旅行规划](../modules/planning.md)、[模型上下文](../modules/context.md)。维护者按契约定位内部实现；普通调用方不持有供应商调度、历史分页或两份可变消息状态。
