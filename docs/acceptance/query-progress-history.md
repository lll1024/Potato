# #112：查询进展折叠、可靠保存与跨设备回看

2026-11-07，在 #111 的独立进展通道之上实施，以真实规划、上下文、HTTP／SSE、SQLite、SessionAccess 和 Web／iOS 页面验证。所有描述和截图来自本次临时隔离服务，不使用日常数据库。

## 交付行为

- 简短模型行动说明随成功的查询请求完成事实提交；工具行动／状态随对应生命周期事实提交，网络等待不进入数据库事务。没有文字分片写库或新 schema，也不由客户端写入模型协议。
- 公开历史每轮返回 `query_progress`，按可靠事实的首次条目次序和最后保存状态重建；旧记录没有元数据时为空，旧服务缺字段时保持原阅读路径。当前预览与历史选择其一，不拼接、不混入旅行行程或复制正文。
- 模型失败的临时说明不保存为进展。事实事务失败时关联元数据一起回滚；实际成功但未保存的工具返回不成为已保存成功。重启仅保留原可靠事实，遗留准备／执行状态显示“已中断 · 结果未知”。进展事实已保存不等于最终回答已保存，两者分别提示。
- Web 用原生 details，iOS 用 DisclosureGroup。查询期间展开；正文首次非空时自动收起，历史带回答时默认收起；主动展开后不会因后续正文增长再次收起。展开按顺序显示行动说明与取得资料／失败／未执行／结果未知，取得资料不称完成核实。
