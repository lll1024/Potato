# 模型请求重试验收

规格：[Issue #53](https://github.com/lll1024/Potato/issues/53)。设计：[ADR 0004](../adr/0004-bounded-model-request-retries.md)。验证日期：2026-10-12。

## 行为与边界

Web 和 CLI 共用 `agent_loop` 的当前步骤重试。首次请求后最多追加 5 次尝试，单次请求超时仍为 60 秒，SDK 不自行重试。认证、配额、上下文超限、参数及未知错误不重试；限流、服务端错误、超时、连接故障及没有内容块的空响应可重试。只有工具调用但没有文字的响应有效；响应加工及存储错误不重试。

本地退避从 500 毫秒指数增长，上限 10 秒，使用 ±10% 抖动。有效且不超过 10 秒的 `Retry-After` 优先按原值等待；超过上限直接结束，缺失或无效时使用本地退避。默认 5 次本地等待约为 0.5、1、2、4、8 秒，加上各次 SDK 请求耗时；没有额外的整轮时间上限。

重试保持同一对话轮次、逻辑步骤、时间与偏好快照、工具结果；不追加用户需求，不重跑已完成工具，不额外消耗逻辑步骤或工具预算。每次实际 attempt 有不同请求身份和顺序，步骤与 attempt 通过已持久提交的开始事件关联，兼容旧数据且无需数据库迁移。失败 attempt 的消息、应用提示和诊断不会加入自动重试的模型输入；实际收到的用量仍保留，未返回则保持未知。

安排等待、退避结束后的恢复和实际 SDK 请求开始分别记录。对话和轨迹可展开重试记录，轨迹时间线增加等待与恢复边界；恢复事件本身不计一次实际请求。出现重试的运行轮次可在两种视图中停止；等待中停止立即结束，在途请求仍按原契约记录真实返回，停止后不发新尝试。耗尽后明确显示最终失败；人工继续开启新轮次，服务重启仅收束中断记录，不重放定时器、请求或工具。

错误记录保留标准分类、原始异常类型、服务状态与请求身份、Retry-After 和脱敏原因链。认证诊断使用固定提示，丢弃可能包含凭证片段的服务原文；其余诊断经过现有完整载荷脱敏流程。

## 验证方式

- `tests/test_model_retry.py`：查询循环验证分类、退避、Retry-After、空响应、6 次耗尽、步骤预算重置、日期与偏好不刷新、工具结果保留和三个停止边界；真实 HTTP/SSE 与 SQLite 验证持久轨迹、真实未知用量、脱敏原因链、鉴权提示、等待中停止及存储故障阻止后续请求。
- `tests/test_recovery.py`：真实 Anthropic 客户端、HTTP 429 与进程强制退出验证重试等待已提交而请求未再发出，重启后只收束，人工新输入不恢复中断协议。
- `tests/test_exception_experience.py`、`tests/test_trace.py`：终态故障夹具明确为不可重试的账户配额故障，继续验证原资料、协议上下文、人工新轮次、去重及原始载荷。
- `frontend/tests/ui/conversation.spec.ts`：验证重试次数与延迟、可用停止接口、停止状态、最终失败、实际 attempt、等待和恢复边界；桌面 1440px 与手机 390px 截图检查无溢出。
- `frontend/tests/presentation.test.mjs`：未发出的重试只有等待边界，不伪造模型请求条；既有正文和 Markdown 安全检查继续执行。

## 实际服务范围

自动验证使用可控外部模型和地图返回，包括真实 SDK 对本地 HTTP 429 的处理。没有消耗生产模型或地图额度，也没有用真实故障复现截图中的底层连接问题；对生产兼容服务未识别的错误按未知分类直接结束，不宣称服务已恢复。关闭页面继续后台运行，服务重启不自动续跑，人工新轮次仍可能再次查询。

## 验证结果

最终后端完整回归 232 项通过（包含 12 项模型重试测试及参数化场景）；前端呈现与 Markdown 安全测试 9 项通过；受影响的会话、异常恢复及正式服务浏览器回归 24 项通过。Python 类型检查 0 错误，TypeScript 检查及 Vite 生产构建通过；设计检测无发现，桌面与手机成组截图检查通过，暂存差异无空白错误。

完整回归曾发现 CLI 临时目录复制清单漏掉新增模块，已修正并单独复测，再运行完整套件通过。Spec 审查修复兼容服务身份头后再次完整验证通过。未将早期失败或尚未完成的测试记为通过。
