使用实际配置的当前模型，通过正式 HTTP/SSE 服务、真实共享查询循环与 SQLite 验证；浏览器采用正式服务与可控外部模型检验机制，真实语义运行中的摘要及旅行回答全部使用实际模型。地图为替身，酒店和来源信息是明确标识的控制事实，不代表已核实的现实酒店政策。

## 失败与修复

[修前失败证据](context-compaction/failures-before-fixes.json.gz)保留真实输入、回答、调用与公开状态，机械 checks 不等于语义通过。

1. 40,000测试窗口下，当前原文或最近必保工具组占满预算，明确 `context_budget` 终止；不能靠截断保留部分制造成功。改用60,000保守窗口后运行完整质量场景，并将来源短事实与无关压力背景分成独立原始记录，避免回读背景把测试预算重新占满。
2. 来源的发布/适用日期和“10月14日开放吗”被日期解析误当旅行改期。HTTP红测试后窄修已确定日期继承，仍支持明确改期、前置“出发日期确定为2026/10/14”、日期后出发动作及纯日期澄清。初始未确定旅行时混在一条输入里的多个来源日期，曾导致歧义；后续验收先独立确定旅行日期，再提供来源原文，不删除来源日期或最终10-14政策问题。
3. 摘要曾遗漏B的发布时间，补充明确区分 published/retrieved/applicable、正文/摘录与身份状态；真实摘要保存A检索10-12、发布/适用未知，B发布10-10、适用10-13。
4. 旧助手复述的长期“不吃辣”被当作本次临时条件，严格种子压缩组仍曾失败。偏好包装明确当前有效记录（包括空列表）及用户原文临时要求优先；摘要规则进一步禁止将旧助手偏好复述/推测晋升 `travel_conditions`，同时保留用户更早明确的有效要求与有效摘要条件。修后严格同种子修后两组均正确；额外身份规则明确未核实不等于非官方，候选规则明确可重新比较但不自动替换，均有限定向真实复验通过。

上下文压缩仍是有损整理；格式检查、来源回读与以上样本不构成无损保证。当前证据只代表明确列出的模型、配置、控制事实和实际运行，未将地图替身当现实旅行核实，也未宣称普遍省费或加速。

## 重现

从项目依赖环境显式运行：

```sh
PYTHONPATH=tests .venv/bin/python tests/context_semantic_eval.py --env-file /path/to/authorized/.env --output /tmp/context-real.json
PYTHONPATH=tests .venv/bin/python tests/context_semantic_eval.py --paired --case dates_preferences_sources --env-file /path/to/authorized/.env --output /tmp/context-paired.json
PYTHONPATH=tests .venv/bin/python tests/context_semantic_eval.py --case cli_low_pressure --case empty_preferences --env-file /path/to/authorized/.env --output /tmp/context-entrypoints.json
cd frontend
npm run build
npm run test:ui -- tests/ui/context-compaction-live.spec.ts
```

脚本不输出 endpoint、凭据或异常原文，`--case` 支持有限定向重验。默认运行不代表自动通过语义验收，仍须核对证据中的实际回答。#64不合并主分支、不关闭父规格；最终合并另行授权。
