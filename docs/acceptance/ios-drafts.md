# iPhone 持久草稿与编辑竞争（#91）

2026-11-04，以 `e16bdae` 为实施与审查基准，继续 `codex/ios-client` 和 PR #96。范围为 [#91](https://github.com/lll1024/Potato/issues/91)，继承父规格 [#88](https://github.com/lll1024/Potato/issues/88) 已确认的共享 `SessionAccess` 测试边界。工作区原有术语表、领域设计和调研材料保持原样，不计入本次交付。

## 交付行为

手机 GRDB 文件按服务、持久数据集及可空会话保存每次编辑的完整草稿和版本，保存不等待网络。最后确认的数据集随服务保存，使重启后离线仍能找回草稿。首次连接前输入在首次确认时绑定，已知数据集变化隔离旧草稿。页面返回、释放及重启不依赖临时输入状态。保存失败显示未保存、保留当前文字并提供重试；离线可编辑，禁用发送，重连不自动提交。

原提交的身份、原文和原始可空目标与草稿分开保存；提交同时捕获匹配草稿版本。有效接受结果原子清理匹配版本与待确认材料，保留较晚编辑，包括改动后改回相同原文。当前新建页收到接受结果后，较晚编辑原子移到真实会话；已离开的页面不迁移其他页面的新建草稿。迁移冲突或写入失败保留来源，不覆盖目标。

## 验证依据

环境为 Xcode 27.2（27B52）、Swift 6、最低 iOS 17；实际运行 iPhone 17 Pro / iOS 26.5 模拟器。依赖精确版本与解析文件保持原样。

公开 `SessionAccess` 和真实 GRDB 文件覆盖：逐会话及服务/数据集隔离、重开与原文空白、首次离线绑定、前台重连不自动发送、未知提交原文不可改、版本匹配清理、改回相同原文、较晚草稿随接受会话保存、来源/目标竞争以及写入/清理事务回滚。SQLite 触发器只用于文件系统边界故障注入，持久化断言通过公开能力重开读取。

XCTest 通过真实 localhost HTTPS / FastAPI / SQLite 验证两个 VIPER module 的外部流程：已有会话与新建页的独立编辑、返回列表与页面释放、App 终止与重开、离线保存及禁发、同页较晚输入随接受会话恢复，以及接受前重开的新建页同步清理原文。仅延迟真实后端的 HTTP 接受响应，不复制后端提交业务。

最终完整 iOS suite：**42 项测试，含参数化共 60 例通过，0 失败、0 跳过**。Swift Testing 33 项、XCTest 快照 3 项、原生界面流程 6 项。机器统计见 [test-summary.json](ios-drafts/test-summary.json)，命令与实际输出节选见 [validation.txt](ios-drafts/validation.txt)。iPhone arm64 无签名构建通过；夹具 pyright、模块结构、文档导航和差异格式检查通过。本次无后端或 Web 生产改动，既有全仓库回归仍按 #89 的版本证据解释。

先失败后通过的行为证据：

- 恢复测试先报告三个独立草稿均无法从文件恢复，实现持久保存后通过。
- 接受测试先报告旧草稿未清理，原子版本清理后通过；较晚版本、改回相同文字及其他会话均保留。
- 新建页较晚草稿迁入真实会话测试先失败，实现原子迁移后通过。
- 首次离线草稿连接后丢失的测试先失败，实现首次绑定与旧作用域解析后通过。
- XCTest 导航测试先报告三处输入为空，接入共享草稿后通过。
