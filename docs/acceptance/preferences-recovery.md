# 后台偏好恢复与有限重试验收（#38）

验收日期：2026-10-10。以下使用实际应用生命周期、公开 HTTP、临时 SQLite、替身外部模型和可控时钟。真实进程案例运行 uvicorn 与 AsyncAnthropic SDK，并实际 kill/restart；它们证明恢复、协议与保存行为，不代表真实模型语义已经验收。完整语义评估由 #39 承担。

## 实施策略

- 每批请求前以短事务写入 `processing`、增加已发出次数并保存资格 generation；模型请求期间不持有 SQLite 事务。公开偏好接口区分 pending、processing、failed、cancelled，已完成输入不显示为待处理。
- 每个有效输入最多发出 3 次提取请求，首次失败后等待 30 秒，第二次后等待 120 秒；生产请求截止为 60 秒。请求异常、超时、无效 JSON、未完整结束或非法变更都采用这条策略。达到上限后停止自动请求，已有偏好保留。
- 重启遇到 processing 时，保留已消耗次数并从重启时刻等待相应退避，再核实会话最后一轮结束后满 3600 秒；已持久保存的 pending 退避时间不因再次重启而重置。第三次中断恢复为 failed。
- 新输入使旧 generation 失效；实时结果或重启恢复都将旧 claim 退回 pending，并退回该次尝试计数。旧结果不提交，也不耗费新闲置资格下的有限重试。Cancelled 保持终态。
- 中断的主轮次由现有 Store 恢复为 terminated，仅为启用后的未结束输入补上保守的重启结束时间；不扫描旧聊天、不重放主模型请求或地图调用。停止后立即中断也补齐闲置计时事实，不恢复被取消的输入。
- 偏好条目与 completed 进度在同一事务提交；真实 SQLite 失败沿用服务存储保护，暂停接受输入与后台处理，保留最后成功事实。不会把存储异常写成普通提取失败后继续调用模型。

## 实际观察

| 场景 | 结果与证据 |
| --- | --- |
| 闲置 3599 秒后 kill/restart | 没有提取；再推进 1 秒才提交。之后重启仍一份偏好；原主轮次、模型请求、地图记录完全保留，没有重放。 |
| 提取请求中 kill | 公开状态先为 processing/1；恢复 pending/1，29 秒内没有重试；再重启后推进 1 秒成功，不重复计数或保存。 |
| 连续三次请求中 kill | 重启后次数依次保留，最后 failed/3；再推进一天也不发起第四次请求。 |
| 提取期间续聊后 kill | 恢复两轮 pending/0，等待新的完整一小时后批量提取两轮输入；旧 claim 不消费新资格的请求次数。 |
| 外部响应后、写锁阻止提交时 kill | 外部已生成并返回响应，SQLite 写事务被锁阻止；进程终止后列表为空、次数保留，解除锁和恢复退避后只保存一次。没有宣称观察到子进程完成响应解析。 |
| 外部响应后进度提交故障 | 真 SQLite trigger 在 completed 进度更新时拒绝写入；公开 storage_error 使服务暂停，新提交返回 503，偏好 INSERT 一并回滚。processing/1 保留，推进时间也不再调用模型；移除故障重启后一次提交，后续重启不重复。 |
| 提交后 kill | 条目身份、内容、版本、来源、处理进度跨重启保持；没有重复提取。 |
| 编辑或删除时旧提取仍在等待，再 kill/restart | 用户管理结果及版本/类别水位保留；旧饮食输入不撤销管理，其他类别照常保存。新会话的实际外部模型输入使用管理后的结果。 |
| 停止末轮后立即 kill | Cancelled 输入跨重启保持取消，不进入提取；之前的有效输入在新的完整闲置一小时后保存。 |
| 读取偏好时真实存储故障 | 主查询不启动，公开 unsaved_fact 为 turn.context，轮次没有伪造 finished/execution_error，服务拒绝新输入。 |
| SDK 请求错误、实际等待超时、无效输出 | 3 次上限、30/120 秒退避与最终失败均通过公开接口观察；已有偏好不变，普通旅行回答继续可用。主旅行请求自身失败也不撤销已保存偏好。 |
