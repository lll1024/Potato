# iPhone 新建、续聊与完整回答（#90）

2026-11-04，在 #89 的 `f0b5e30` 基础上继续 `codex/ios-client`。范围以 [#90](https://github.com/lll1024/Potato/issues/90) 和父规格 [#88](https://github.com/lll1024/Potato/issues/88) 为准；保留工作区原有领域文档和调研修改。

## 交付范围

共享 `SessionAccess` 提供发送、待确认材料、接受状态、可发送状态、当前对话观察与唯一前台轮询。GRDB 在 POST 前原子保存服务地址、持久数据集身份、提交身份、原始输入和原始可空目标。新建及续聊复用 `/api/turns`，接受后使用返回的真实会话和轮次；后端仍独占旅行规划、历史、旅行者偏好及全局名额。

会话列表增加新建入口，对话底部增加多行输入和发送反馈。接受后读取真实快照及完整历史，前台约每两秒统一核对，不把接受当作完成，不为输入排队。明确拒绝、本机保存失败和结果未知分别反馈；未知保留原始材料，重启仍可读取其归属，暂不自动核对或重发。

## 验证证据

环境沿用 #89：Xcode 26.5、Swift 6、iOS 17 部署下限、iPhone 17 Pro / iOS 26.5 模拟器。依赖版本保持原锁定组合。

- 公开 interface 的首个测试先报告「发送前必须持久保存待确认提交」，实现后通过。轮询测试先报告缺少共享对话投影，实现后通过。
- 真实文件 GRDB 验证 POST 前重开读取原始记录；SQLite 故障触发器验证保存失败时没有 POST。验证重复点击、明确 409/422/503、响应丢失、非法 202、身份或目标错误、代理异常及配置变化后的迟到接受。
- 可控时间与 HTTP 边界验证唯一轮询、两秒等待、持久完成回答、供应商暂停仍可用、后端未保存和网络异常保留最后 running 事实。
- 真实 HTTPS / FastAPI / SQLite 集成通过新建、相同身份原始 POST 重发、续聊及双客户端完整历史一致性；同一新会话第一次输入仅一个轮次，重发返回相同身份。偏好后台通过公开 HTTP 种下「不吃辣」，控制闲置时钟提取；后续两轮的外部模型请求读取共同偏好，保存回答包含对应标记。
- 模拟器 XCTest 通过「新建 → 输入 → 发送 → 完整回答 → 续聊 → 完整回答 → 返回列表」，完整回答包含共同偏好标记。测试数据不代表真实旅行事实。

最终完整 iOS suite：**26 项测试、含参数化共 39 例通过，0 失败、0 跳过**。Swift Testing 21 项、XCTest 快照 3 项、完整 UI 流程 2 项；机器汇总见 [test-summary.json](ios-submission/test-summary.json)，命令及输出节选见 [validation.txt](ios-submission/validation.txt)。iPhone arm64 无签名构建通过，部署下限仍为 iOS 17。原后端公开提交契约 10 项、集成夹具 pyright 0 错误、模块结构、文档导航及差异格式检查通过。本次没有修改后端或 Web 生产代码，#89 的原有全仓库回归按原验收版本解释。

## Standards

首次独立审查发现 2 项 P2：轮询 404 未向页面发布错误、Interactor 承担文案映射。现通过公开 `conversationFailure` 表达读取失败并清除恢复后的旧错误；两个 Interactor 仅提供领域状态，Presenter 复用状态文案映射。复核两项均消除，无剩余实质规范问题或需单列的代码气味。

## Spec

首次独立审查发现 2 项 P2：迟到发送回调可能夺回已离开的会话目标，发送前发起的旧空闲快照可能解除接受屏障。现按页面可见性限制回调更新，且只采用接受后发起的核对解除屏障。公开 interface 的旧快照测试、真实延迟 HTTPS 接受后的页面切换测试及轮询 404 测试，均在临时恢复旧行为时明确失败，修正后通过。复核未发现剩余实质规格问题、缺失或范围扩张。

首次 Standards 2 项、Spec 2 项，各自最高 P2；最终 Standards 0、Spec 0，均无遗留最高严重项。审查固定点 `f0b5e30`，仅比较本任务暂存改动。
