## 交付行为

两个页面读取同一个 App 级全局状态，任一设备执行时明确忙碌，不自动排队；`accepting` 与当前空闲独立判断。列表与对话提供停止入口，对话按钮固定在工具栏，长历史底部也可直接操作。每次操作捕获服务地址、持久数据集、会话及原轮次，不随后续导航或新轮次改变目标。

停止 POST 只确认请求响应。共享状态区分正在请求、等待真实收束及暂不能确认；请求完成后发起的新快照确认原轮次已释放，才能开放下一次发送。取消、断线、坏响应和错误身份不能生成任务终态。旧目标已结束后请求原身份，不会停止后来的轮次；配置或数据集变化使迟到响应失效。

前台立即刷新全局、未确认提交及相关历史，然后每次核对后约两秒再轮询；重复前台通知不增加循环。后台停止客户端读取，页面释放、取消读取与断线均不调用停止接口；电脑继续执行，返回前台补齐保存结果。刷新、历史、页面和归属版本共同屏蔽旧响应；连接投影另按统一的读取次序采用结果，较旧的列表失败不能覆盖较新的历史成功。

连接中断表示暂不能核对，保留最后成功的事实；后端保存故障及未保存事实单独显示并禁止新输入。轮次展示沿用真实 `status` / `reason` 区分模型失败、预算、停止与重启中断。原后端在调用边界处理停止；若在途调用已经给出最终回答并保存为完成，手机仍忠实显示完成，不按本机停止意图强改终态。本任务未修改后端、Web 或 CLI 的生产业务规则。

## 验证与限制

环境为 Xcode 27.2、Swift 6、iPhone 17 Pro / iOS 26.5 模拟器，部署下限保持 iOS 17。HTTP 传输边界控制断连、迟到响应与错误身份，真实 GRDB 文件保存客户端材料；轮询间隔通过 `PollClock` 控制，无需等待真实两秒。公开测试覆盖前后台立即恢复、后台取消慢读取、重复前台通知、电脑发起忙碌、原目标停止、未知停止、释放前禁止发送、服务切换及两种方向的连接竞争。

真实 HTTPS 集成在 18494 启动公开 `create_app` 与临时 SQLite，仅通过事件挂起外部模型返回。手机停止时，快照仍显示活动轮次和停止中，第二个客户端真实 POST 返回 409；释放调用后才保存 `user_stop` 并开放输入。随后发起新轮次、停止旧目标，核对新轮未受影响；手机后台期间电脑完成，回前台读取完整回答，两个客户端历史完全一致，未发送草稿保留且没有自动创建轮次。

## Standards

首轮 1 项 P2：旧列表失败仍可能覆盖较新的历史成功连接。新增公开入口反例先失败，再加入连接投影读取次序保护。另采纳长历史停止按钮可达性建议，将按钮固定到工具栏并新增实际点击验证。最终复核 **0 项遗留、0 项新增**。

## Spec

累计发现 2 项 P2：连接竞态违反“慢响应或迟到响应不能覆盖更新状态”；组合复核发现未知或隔离提交的恢复面板可能遮住独立保存故障。后一项经公开能力构造未知提交、保存故障快照及核对断线，页面可见投影先报告 `nil`，修复后同时保留原恢复提示和保存故障。停止目标、真实收束屏障、前后台生命周期与真实双客户端行为符合规格；没有实质范围扩张。最终复核 **0 项遗留、0 项新增**。

## 演示步骤

1. 按 [iOS README](../../ios/README.md) 启动五个测试 HTTPS 服务；模拟器配置 `https://localhost:18494`。
2. 运行 `SubmissionIntegrationTests`，事件控制外部调用，观察真实全局忙碌、停止中 409、释放后持久终态及旧目标隔离。
3. 运行 `NavigationTests.testCrossDeviceStopSurvivesNavigationAndBackgroundCompletion`，查看对话和列表共享停止状态、主屏返回补齐结果及长历史固定停止入口。
4. 运行 `PollingTests`、`StopTests` 与 `ConnectionFailureTests`，通过受控调度复现取消、重新进入前台、原目标及迟到响应；不使用随机互联网或付费模型判定正确性。
