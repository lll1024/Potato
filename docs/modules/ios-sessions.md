# iOS 助手会话能力

本客户端通过现有[助手会话 HTTP 契约](sessions.md)访问同一后端。后端六项能力、Web/CLI 与数据目录锁保持原样。当前覆盖 #89 的配置与完整阅读、#90 的新建、续聊、发送前保存与共享前台轮询、#91 的独立持久草稿、#92 的未确认提交恢复、#93 的跨设备停止及前后台恢复、#94 的更早分页与回答排版，以及 #99 的最终回答实时阅读、#100 的当前正文恢复与失效隔离。#95 的安装、连接及维护步骤见[交付说明](../../ios/DELIVERY.md)；本机复验、全部故事映射及尚缺的真机／分发证据见 [#95 验收](../acceptance/ios-delivery.md)。

## 阅读入口

- `ios/SessionKit/SessionAccess.swift`：Interactor 使用的公开 interface、连接状态与领域数据。
- `ios/SessionKit/SharedSessions.swift`：App 生命周期内唯一共享实例；地址配置、原子提交材料、接受身份、连接核对、唯一前台轮询／正文订阅和服务失效规则。
- `ios/Potato/AppAssembly.swift`：FactoryKit 装配，解析一次共享能力后通过构造参数注入两个 Interactor。
- `ios/Potato/SessionList/` 与 `ios/Potato/Conversation/`：两个 VIPER module；View 只显示状态与转交操作，Interactor 调用公开能力，Presenter 提供 Observation 展示状态，Router 管理进入、返回与连接设置。
- `ios/Potato/Settings/`：简单连接配置入口。

## 状态归属与读取

全部操作在 MainActor 使用。App 通过 `SharedSessions(databaseURL:)` 打开手机端 GRDB 客户端文件；构造失败显示本机配置不可用，不伪造尚未配置。两个 Interactor 只接收 `any SessionAccess`。

| 公开操作 | 结果与失败 |
| --- | --- |
| `configure(address:)` | 短事务保存规范化地址；空串清除配置。校验或保存失败保留原配置；成功使旧请求失效 |
| `refresh()` | 返回 `SessionList`，更新共享连接与 `ServiceState`；列表失败抛错，不返回假空列表 |
| `history(sessionID:)` | 返回 `ConversationPage`，含完整轮次、下一页位置及数据集身份；404 独立表示会话不存在；更新正在观察的对话 |
| `submit(input:sessionID:)` | 先保存原始请求，再 POST；返回关联原请求、真实会话和轮次的 `SubmissionReceipt`，只表示已接受 |
| `canSubmit(draft:)` / `submit(draft:)` | 页面通过草稿提交；共享能力核对捕获服务及已绑定数据集，过期草稿不可发送，`submit` 抛 `obsolete` 且不 POST；原文发送入口保留给未持有草稿的调用方 |
| `reconcileSubmission()` | 重新读取快照与列表，在确认服务和数据集后查询原提交；未知抛 `submissionUnknown`，已删除及冲突保持各自错误 |
| `canRetrySubmission` / `retrySubmission()` | 仅最近核对为未见接受记录时开放显式重试；操作内再次读取身份和接受记录，必要时 POST 原身份、原文及原始可空目标 |
| `watchConversation(sessionID:)` | 指定观察的对话；切换使旧历史和正文订阅失效，空目标用于新建页或退出页面 |
| `stopTarget` / `stopState` / `stop(target:)` | 捕获服务、持久数据集、会话及原轮次；POST 原目标，等待新快照确认释放。未知结果保留核对屏障；旧目标不停止后来轮次 |
| `setForeground(_:)` | 幂等启停唯一轮询及正文订阅；前台先恢复快照和历史，再接收实时正文；轮询约两秒核对持久状态；取消读取不停止后端任务 |
| `draft(sessionID:)` | 同步读取当前服务、最后确认数据集及可空会话的草稿；失败抛 `draftLoadFailed`，不伪造空草稿 |
| `saveDraft(input:scope:)` | 按捕获的 `DraftScope` 同步保存原文，返回新版本；失败抛 `draftSaveFailed`，保留上次已保存内容 |
| `moveDraft(_:input:to:)` | 新建页接受后，将当前编辑内容原子迁入真实会话；仅迁移仍匹配的来源，不覆盖目标已有文字；失败保留来源并抛 `draftSaveFailed` |

`SessionFailure.obsolete` 表示响应所属配置、数据集或读取次序已过期，不能作为当前页面结果。配置变化返回列表；数据集身份变化清除旧页面，必要时重新读取列表。其他错误以可理解文案展示，保留错误与后端终态的区别。

共享能力拥有服务地址、连接状态和后端快照；连接状态与后端可接受输入、忙碌、停止及保存故障分开。配置存在不表示连接已成功，只有真实 HTTP 核对成功才显示已连接。页面局部加载和读取错误归 Presenter，页面释放不会停止后端轮次。

配置接受无用户名、密码、查询、片段或子路径的 HTTPS 服务根地址，使用系统证书校验。仅模拟器 Debug 额外接受 `http://127.0.0.1` 的服务根地址及有效端口；App 装配在没有保存地址时预置 `http://127.0.0.1:8000`，已有地址保持不变。本地 HTTP 的 ATS 例外仅注入模拟器 Debug 的 App。真机及其他构建仍只接受 HTTPS，恢复本机配置时也按当前构建校验地址。

不存模型或地图密钥。地址通过 GRDB 短事务保存。保存失败不切换内存配置。App 重启从同一文件恢复配置并重新核对连接，不恢复虚构的“已连接”。手机不复制后端完整历史。本地 HTTP 连接失败时显示“无法连接本地服务，请确认后端已启动”并沿用列表重试入口；HTTP 状态和解码错误仍显示各自原因，不将连接失败直接判为后端未启动。日常后端由用户单独启动，运行方式见 [本地模拟器调试](../../ios/README.md#本地模拟器调试)。

列表读取 `GET /api/snapshot` 与 `GET /api/sessions?limit=50`；对话使用 `GET /api/sessions/{id}?limit=50&summary=false&include_messages=false`。`input`、`answer` 保持完整原文，只排除底层模型协议。`loadMoreSessions()` 原样传回不透明 `next_cursor`；`loadEarlierTurns(sessionID:)` 原样传回后端 `next_before`，仅作用于当前观察的会话。`isLoadingMoreSessions` / `isLoadingEarlierTurns` 防止同类重复加载，`moreSessionsFailure` / `earlierTurnsFailure` 提供独立失败与显式重试；普通网络或分页错误保留已读内容和继续入口。历史 404 清空当前会话投影、显示不存在，并使更早的成功响应失效。

列表按会话身份去重，较旧分页不替换当前标题；刷新重新读取已展开的页数，反映电脑端新内容、改名与删除。列表刷新与继续加载依次读取，避免迟到旧页重新带回已删除记录，也避免慢分页被轮询反复作废；全局快照仍先独立读取。游标仅用于请求，不从游标推断会话顺序或归属。

历史按轮次身份去重、后端 `ordinal` 排序；每轮分别记录其被读取时的事件 `cursor`，较旧响应不能替换较新的完成事实，较新的旧页也能补上早已离开最新页的轮次终态。实际读取的连续区间保留各自的后端继续入口；刷新产生的新历史缺口优先补齐，迟到旧页不能关闭这个缺口，补齐后继续向更早范围读取。已加载历史只保留在当前共享内存投影；退出页面停止观察，切换服务、数据集或会话使旧目标的分页失效，不向手机数据库复制历史。

更换地址使旧读取失效；重复刷新只采用较新的结果。服务身份来自持久 `stream_id`，普通重启不凭进程身份推断为新数据集。网络、HTTP、解码和会话不存在分别表达，错误不能生成空列表、空历史或后端失败终态。取消客户端读取不调用后端停止接口。

`sessionList`、`conversation`、`conversationFailure`、`submission`、`pendingSubmission` 和 `canSubmit` 是共享可观察投影。轮询依次核对快照、列表及当前对话，网络失败保留最后成功的持久事实并显示连接不可用；保存故障保留 `storageError` / `unsavedFact`，禁止新输入。地图供应商暂停不独立阻止发送。两个 Presenter 不维护各自的轮询或全局名额。

## 实时正文（#99）

`SessionAccess.answerPreview` 是当前观察会话的可选 `AnswerPreview`，包含服务进程 `instanceID`、数据集 `streamID`、会话 `sessionID`、轮次 `turnID`、尝试 `attemptID`、递增 `revision`、累计 `text` 和 `status`。`answerFailure` 单独表示实时接收错误；不会将网络错误写成后端失败终态，也不清除最后已保存历史。没有流式字段的旧服务继续通过既有轮询读取完整回答。

共享能力在前台恢复 `GET /api/snapshot` 的当前正文与服务身份，读取当前历史后使用现有 `GET /api/events?stream_id=...&after=...`，从已读取历史的持久游标接入，避免重放整库轨迹。同一时间只有一个正文订阅；重复前台通知或重复观察同一会话不另建连接。页面及 Presenter 不操作传输。流式传输独立于普通 HTTP 的短总时限，使用服务心跳保持接收；按完整 SSE 事件投影累计正文，网络块可截断 UTF-8 中文或事件行，不进行逐字播放。

只采用当前连接身份、当前进程、数据集和活动轮次的正文，相同或低于已见 `revision` 的更新失效。不同尝试整体替换，不能拼接；`invalidated` 清空原尝试文字，带次序的 `null` 明确表示预览缺失，重复消息不能使其复活。服务进程变更时清除预览，即使 `stream_id` 未变也重新核对；订阅先发现进程变化时立即使旧预览和在途旧快照失效，再读取真实状态。配置、数据集、会话变化、会话 404、退出页面或离开前台均取消客户端接收，使旧连接回调失效。切换观察会话时清除正文及其展示次序，新连接可恢复同次序的有效累计对象，原连接仍按操作身份失效。后台／锁屏不发送停止请求；恢复前台先读累计快照，断线后由后续前台核对先恢复快照和历史，再重建订阅；离开期间已保存时采用真实历史。完整重连竞争、同库重启和实际前后台交互见 [#100 验收](../acceptance/answer-recovery.md)。

预览与 `ConversationTurn.answer` 分开；历史仍为 `running` 时可读取多批正文，不能将其视为已保存。Presenter 通过同一轮次投影预览和“正在生成 · 尚未保存”／“正在保存回答”，复用 `AnswerView` 的 Markdown。复制预览使用“复制当前正文”；持久终态优先使用历史回答，迟到预览不能覆盖已保存结果。两端使用相同提交与接受身份，不另建手机专用轮次。错误重试与降级见下文 #101；停止／未保存正文体验和长文滚动打磨分别由 #102、#103 继续验收。

验证通过公开 `SessionAccess`、可控分块 HTTP 传输、真实 GRDB 文件与后端临时 SQLite；少量界面测试验证多批正文在最终响应返回前真实增长，再转为一致的保存历史。步骤及证据见 [#99 验收](../acceptance/ios-answer-streaming.md)。

## 发送边界

`submit` 保留原始输入（只以去空白副本判断是否为空），在 GRDB 同一短事务中保存提交 UUID、规范化服务地址、持久数据集身份、原始输入及原始可空目标，再发送 `POST /api/turns`。网络等待不持有数据库事务。本机保存失败抛 `localSaveFailed`，不发送并由输入框保留原文。发送中重复点击被拒绝，不创建队列；未知记录存在时禁止新身份发送。

新会话的原始目标为空，接受结果中新生成的会话不回写原请求。只有 schema、提交身份和目标一致的 202 才转换为接受结果；接受后清理匹配记录，等接受后发起的真实快照核对后解除本机接受核对屏障，完整回答仍只来自历史。已知的忙碌、输入校验、服务不可用和会话不存在分别反馈，释放明确未接受的记录；其他 HTTP、网络、解码或身份不一致结果保留原待确认材料为 `unknown`；内容冲突与已删除身份分别显示 `submissionConflict`、`submissionDeleted`，保留原材料且不允许重试。接受后本机清理失败也保留原记录。

配置或数据集变化时不采用迟到接受结果，也不将旧输入发送到新服务。重新打开本机文件先显示未知；首次共享刷新成功后自动核对，轮询和手动刷新复用同一入口。`refresh()` 先确认快照中的持久 `stream_id` 并读取列表，然后查询 `GET /api/submissions/{id}`；核对失败不使已经读到的列表成为假空列表。

`checking` 期间禁止另一项提交操作；有效 200 使用与 202 相同的身份、目标和 schema 校验，仅关联原会话及原轮次，仍等历史确认真实终态。接受后的原子清理与草稿版本规则和首次发送相同；清理失败保留原记录，重启后再按原身份核对。接受后仍有快照核对屏障，禁止用接受前的空闲状态开放下一次输入。

仅代码明确为 `SUBMISSION_NOT_FOUND` 的 404 转成 `notFound`；它只说明查询时未见接受事实，不承诺原 POST 已结束。该状态不发送输入，只有用户明确选择 `retrySubmission()` 才重新读服务身份与接受记录，若已接受则直接采用 200；仍为 404 时 POST 原提交，不改 UUID、空白或原始可空目标。重试时忙碌、校验、会话不存在和不可用分别显示并保留原请求，下次只能继续核对，不能创建新身份绕过不确定性。410 和内容冲突保留原文及错误，禁用同提交重试；不把后端失败轮次的再次执行混作网络重试。

更换服务或已知数据集变化使旧操作身份失效，旧接受与核对回调不能改变当前投影或清理新草稿；原请求显示 `isolated`，其服务、数据集、原目标及可复制原文在列表与对话中可取回。新服务仍可刷新自身状态，但不会查询或重发旧提交；切回原归属可继续核对。隔离或未决记录仍占本机提交名额，不提供清除记录后绕过核对的入口。同一数据库普通重启保留持久身份，照常恢复。

列表与对话 Presenter 只投影共享状态并调用 Interactor；恢复面板不持有另一份提交状态。接受后提供“打开原会话”，按真实历史取得会话再导航；挂起前捕获导航版本，用户进入新建页、返回或打开设置后旧结果不再导航，404 明确反馈。恢复详情在页面滚动区，长原文另有高度受限的滚动区，大字号操作纵排，不挤出输入框；不会把接受误标成成功完成。页面或 App 生命周期不拥有提交材料。

## 本机草稿

GRDB 文件以规范化服务地址、持久 `stream_id`、可空会话身份为联合归属；空会话是该服务的新建页槽位。每次编辑立即完成一个短事务，不依赖防抖、页面退出回调或网络。空文本同样保存，避免重启恢复已删除的文字。每次保存生成新版本，即使用户改动后恢复成相同文本也属于较晚草稿。

每个服务最后确认的数据集身份持久保存，使离线重启仍能找到其草稿。首次连接前的离线草稿暂以空数据集归属，首次核对成功时在同一短事务中绑定；首次绑定另行保留，旧空作用域不会随后来的数据集变化重新绑定。之后已知数据集变化不迁移旧草稿。旧页面捕获的服务与已知数据集归属不随配置切换改变；切回服务或原数据集可取回原草稿。草稿仅保存在手机，不复制后端历史，也不跨设备同步。

发送前在保存待确认材料的同一事务中记录匹配草稿的版本。待确认原文与草稿分开，编辑不会改写提交身份绑定的内容。收到有效接受结果后，在同一事务中删除待确认材料及版本、原文、归属仍匹配的旧草稿；明确拒绝保留草稿，未知或清理失败保留原提交。清理事务失败不留下半完成状态。

Presenter 显示本机保存状态；读取失败时禁止编辑并提供重读，写入失败保留当前编辑原文、显示未保存及重试入口，并禁用发送。返回列表、页面释放与 App 重启从共享能力恢复草稿。页面观察共享接受状态，重新读取已提交版本的清理结果，避免重开页面继续显示已删除文字；有未保存编辑时保留编辑原文。接受响应只更新仍可见的原页面：新建页未修改的输入从真实会话读取空草稿，较晚输入随当前页迁入接受的真实会话；已切换到其他页面时不迁移其新建草稿。迁移失败保留原槽位文字，当前页可重试保存。首次离线重连也须核对草稿归属，旧数据集草稿保持可编辑并明确提示，不能投到当前数据集。离线仍可编辑，但明确不能在线发送；重连只读取状态，草稿不排队、不自动发送。

## 前台与停止

App 的 scene phase 在活跃时启用唯一共享轮询、离开活跃态时取消读取；每轮核对后由可注入调度等待约两秒，重复前台通知不启动第二个循环。后台取消、锁屏、页面释放和连接中断不调用停止接口。恢复前台立即读取快照、列表、未确认提交和正在观察的相关会话，补齐离开期间保存的完整结果。取消后迟到响应不能恢复旧状态；全局刷新与历史读取的连接投影只采用较新的读取，历史另按配置、数据集、刷新和页面次序失效。

`stopTarget` 来自真实全局快照，包含规范化服务地址、持久数据集、会话和原轮次。两个页面捕获此值再调用 `stop(target:)`，不在异步返回后重新选择活动轮次。服务或数据集变化拒绝旧操作；原轮次已结束时仍只请求原目标，后端不会影响后来的轮次。`stopState` 区分正在请求、等待收束和暂不能确认。POST 返回只说明停止请求得到响应，不能生成任务终态，也不能解除发送屏障；需要请求返回后发起的新快照确认原目标已释放。网络或响应异常显示暂时无法确认，刷新后继续按事实核对，可明确重试原目标。

停止中仍占全局名额；`accepting` 与空闲分别判断，不排队。后端保存故障及未保存事实优先于普通运行说明，禁止新输入。连接中断只表示暂不能核对，保留最后成功历史；模型失败、预算耗尽、停止、服务重启中断沿用持久轮次的真实 `status` / `reason`。请求停止后若后端原有边界最终保存为正常完成，仍显示真实完成，不能强行改成停止。

## 构建与验证

回答排版由 `AnswerView` 封装 MarkdownUI。完整回答与实时预览均支持系统文字选择、打开链接与复制；复制不截断、不去除 Markdown 标记。表格在独立横向滚动区展示，列宽随 Dynamic Type 缩放，保留中文换行。列表和对话的继续加载经 Presenter → Interactor → `SessionAccess`，Router 仍负责进入和返回；查看更早内容与回到最新均为当前页面的阅读定位，不增加搜索、改名、删除入口。

工程：`ios/Potato.xcodeproj`；生成源：`ios/project.yml`（XcodeGen 2.46.0）。Swift 6，最低 iOS 17，仅 iPhone；依赖解析结果随工程提交。`ios/PotatoTests/` 通过共享公开 interface、真实文件数据库及真实 HTTP／HTTPS 后端验证；`ios/PotatoUITests/` 验证模拟器免配置启动、本地连接重试、设置、进入、返回、草稿重启、离线编辑、分页与完整复制和外链。运行步骤见 [iOS README](../../ios/README.md)；证据见 [本地模拟器调试](../acceptance/ios-local-debug.md)、[#89](../acceptance/ios-readonly.md)、[#90](../acceptance/ios-submission.md)、[#91](../acceptance/ios-drafts.md)、[#92](../acceptance/ios-recovery.md)、[#93](../acceptance/ios-lifecycle.md) 与 [#94](../acceptance/ios-reading.md)。

## 作答失败与降级（#101）

`AnswerPreview.status` 接受 `retrying`，此时共享投影为空正文，Presenter 显示“正在重试，新尝试将从头作答”。新 `attemptID` 的累计正文整体替换；传输读取失败仍使用独立 `answerFailure`，不会触发手机自行重发模型或用户输入。后端失败终态到达后采用历史，不无限显示正在生成。

`AnswerPreview.delivery` 和 `ConversationTurn.answerDelivery` 为可选方式字段，兼容旧服务。`complete` 由后端的明确流式拒绝产生，Presenter 在等待期间及已保存回答旁说明“模型服务不支持流式，改为生成完整回答”。原因与正文分开，保存后仍可通过历史恢复；手机不根据普通网络错误自行推断不支持流式。公开能力与模拟器真实 HTTPS 故障场景见 [#101 验收](../acceptance/answer-retries.md)。


## 停止与未保存正文（#102）

`SessionAccess.stop(target:)` 在发起 HTTP 前冻结捕获轮次的当前正文；`stopState.requesting` 即刻禁止提交。等待或未知结果期间仍冻结，轮询读到远端 `stopping` 同样冻结；订阅继续核对累计正文，不取消后端调用。配置、数据集和进程变化使冻结归属失效，捕获的旧目标不会冻结后来的轮次。原轮次真实保存后使用历史完整回答，已保存终态不被迟到预览覆盖。

原轮次真实收束释放名额后，若服务返回 `storageError` 及关联轮次的 `unsavedFact`，仍接受该轮最新内存正文供当前页面阅读；界面显示“未保存 · 请复制保留，刷新后可能丢失”及“复制未保存正文”。它保持预览身份，不进入已保存历史，`canSubmit` 继续为假。没有正文则只展示真实故障。普通截断与预算终态沿用原原因，正文复制文案使用“不完整回答”，不称完整回答。

验证：公开 `SessionAccess` 的停止／真实保存和未保存结果、旧目标、配置失效见 [PollingTests](../../ios/PotatoTests/PollingTests.swift)；模拟器通过真实 HTTPS／SQLite 检查冻结、保存后全文及未保存复制，见 [ReadingNavigationTests](../../ios/PotatoUITests/ReadingNavigationTests.swift)。
