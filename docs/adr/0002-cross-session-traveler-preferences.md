# 跨会话保存本机旅行者偏好，并与聊天历史独立管理

首版面向本机单一旅行者，在不同助手会话中复用其明确表达的稳定旅行者偏好，并自动保存，以减少重复提供信息。某次旅行的具体安排不作为长期偏好；临时例外仅影响当前要求，明确的长期变化更新已有偏好，无法区分两者时询问旅行者。

自动保存的类别限定为饮食、活动兴趣、交通和住宿喜好。游玩节奏受当前精力等条件影响，首版仅在当前会话中使用，不作为跨会话偏好类别；旅行日期、单次预算、具体酒店安排和同行人的偏好也不保存为本人的长期偏好。助手不依据查询次数或自己的推测生成旅行者偏好。

偏好与聊天历史独立管理：删除助手会话保留已保存偏好；删除偏好后，不从已有聊天自动恢复。保留的原聊天仍可在续聊时提供原文上下文。首版只处理功能启用后的新输入，不回溯提取历史聊天；自动保存不逐次提示，旅行者通过集中管理入口查看、修改和删除偏好。

偏好采用独立后台提取，从助手会话最后一个对话轮次结束起连续闲置 1 小时后再处理，新输入重置闲置计时。会话有正在执行或停止中的对话轮次时视为仍在进行，后台跳过该会话；仅打开页面、阅读历史或编辑未提交输入不影响闲置判定。旅行回答不等待提取完成，以减少记忆处理对回答延迟的影响和连续交流中的重复提取。因此在会话达到闲置条件并完成提取前，新会话可能读不到尚未保存的偏好。已成功保存的偏好独立于旅行回答是否成功，不因查询失败而撤销；稳定偏好不自动过期，直到旅行者明确改变或删除。

后台处理保留尚未完成的提取任务，服务重启后恢复待处理记录，并遵守会话闲置后再处理、跳过仍在进行会话的规则；失败时有限重试，仍失败则在管理页显示状态。恢复仅覆盖功能启用后接收的新输入，不扫描旧聊天。后台发现无法区分临时例外与长期变化的歧义时，保留原偏好，在下一次讨论相关需求时澄清，不在回答完成后突然追加问题。

停止回答同时停止本轮尚未提交的偏好提取，停止前已保存的偏好保留；关闭浏览器页面继续后台处理。用户在管理页修改或删除偏好后，迟到的后台结果不得覆盖该操作。

技术方案复用现有 SQLite，独立保存偏好条目和后台待处理记录，由单个后台处理器按输入顺序处理达到闲置条件的会话，批量提取尚未处理的新输入。跨会话更新以用户输入的先后顺序判断新旧，避免较早会话延迟提取后覆盖较新的表达。每个输入轮次的处理保持幂等，提交前复核会话是否仍满足闲置条件及偏好版本，防止用户恢复聊天或修改、删除偏好后，旧提取结果继续写入。

提取使用独立模型请求，复用现有 Anthropic 兼容客户端。当前新用户输入是新增偏好的依据，已有偏好用于去重和更新，少量会话上下文仅用于解释指代；旧聊天、助手回答和查询结果不得独立产生新偏好。模型提出结构化变更建议，后端校验来源、字段和目标记录后以短事务保存，不跨模型请求持有数据库事务。具体兼容服务的结构化输出能力在实施时验证，不能仅凭协议格式假定严格输出可用。

旅行助手每轮读取有效偏好，并与会话历史分别构造模型输入，不把偏好快照永久混入历史消息。首版不引入向量检索或时序图谱，以保持少量明确偏好的读取和管理可解释；后续确有大量记忆检索需求时，再根据项目案例评估替代方案。

这一边界使聊天清理与跨会话个性化各自可控，但删除聊天不代表同时清除了偏好，管理入口须明确说明二者的关系。后台批量提取减少对连续交流的干扰，也延迟新偏好的跨会话可用时间；模型输出的格式校验不能保证语义判断正确，实施时须验证临时要求、长期变化、第三方信息、删除后不恢复及并发修改等场景。用户已确认上述完整设计，功能实现和运行验证尚未开展。
