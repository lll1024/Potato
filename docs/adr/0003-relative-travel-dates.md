# 按每轮北京时间解释相对旅行日期并保留已确定日期

国内首版统一使用 `Asia/Shanghai`。每个新对话轮次开始时，后端读取当前日期、时间和星期，作为该轮固定的时间上下文提供给模型；CLI、Web 和历史续聊使用相同规则。当前时间由本机获取，不接入外部时间 MCP，以减少调用成本和外部服务依赖。

“明天”“本周末”“下周末”等表达按本轮时间上下文解释，回复时给出对应的具体公历日期并继续规划，不因缺少显式年份而重复追问。每周以周一为首日，“本周末”指本周六、周日，“下周末”指下一周的周六、周日；不安排已经过去的日期，周日说“本周末”时只安排当天并说明周六已过去。若用户指定的天数与有效日期范围冲突，仍须先澄清，不能擅自忽略天数或延到下一周。

已确定的旅行日期在后续对话中保留；跨午夜或重启后的续聊须刷新当前时间，但不能用新的时间基准重新解释历史输入中的相对日期并改动原旅行行程。用户明确修改旅行日期时才更新相关安排。旅行日期属于单次旅行要求，不保存为长期旅行者偏好，遵循 [ADR 0002](0002-cross-session-traveler-preferences.md)。

验收须覆盖工作日、周六、周日的周末解释，跨午夜和跨年的相对日期，显式日期覆盖、天数冲突及历史续聊；正常回答与异常时保留的查询资料对旅行日期的判断须一致。本记录确认设计边界，功能实现与真实模型对话验证尚未完成。
