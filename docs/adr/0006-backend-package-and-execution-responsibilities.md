# 后端迁入单个包，并集中上下文维护与对话轮次运行职责

2026-10-23 更新：本记录中保持单个浅层 `travel_app/` 包的目录取舍已由 [ADR 0011](0011-deep-modules-and-progressive-disclosure.md) 替代，后续改为按完整能力组织深 module，采用独立目录与显式公开入口。下文保留原决策背景；原有启动与数据兼容、运行与停止、上下文维护及存储事务约束继续适用。新设计已确认，已进入 #80 行为基线与校验阶段，六项能力的完整迁移尚未完成。

后端内部模块目前平铺在根目录，缺少职责地图；上下文维护决策分散在模型请求循环的压力处理与超限恢复分支，Web 对话轮次的运行状态由多个闭包共同维护。2026-10-13 用户确认同时解决代码查找与核心流程修改成本，选择迁入单个浅层 `travel_app/` 包，并采用以下兼容范围与职责整理方向。

## 目录与兼容范围

根目录保留 `agent.py`、`web.py` 作为启动入口，后端内部实现迁入 `travel_app/`。现有 `python agent.py`、`python agent.py --check-amap`、`python web.py` 及其参数、退出行为继续有效；仓库内部代码、测试与验收脚本统一使用 `travel_app.*` 导入，旧的顶层 Python 导入路径不纳入兼容范围。

选择实际迁移，而非仅补导航，以减少根目录的职责混杂；先使用一个浅层包，避免在当前规模下增加多级目录的查找成本。补充后端职责地图与验收索引，并明确历史档案身份。`.scratch/` 按[任务跟踪约定](../agents/issue-tracker.md)保留原路径与历史内容，其状态不能作为当前待办依据。

迁移后 `.env` 与默认 `frontend/dist` 仍按项目根定位；显式静态目录覆盖继续有效。默认 `.travel-data` 与相对 `--data-dir` 保留按启动工作目录解析的行为，使已有本机数据继续使用原位置。

## 核心职责

上下文维护集中负责压力判断、确定性整理、摘要额度与超限恢复准备，两个触发位置共用这些决策。模型请求循环继续执行旅行模型步骤与工具调用；普通网络重试和摘要有限尝试分别遵循 [ADR 0004](0004-bounded-model-request-retries.md) 与 [ADR 0005](0005-session-context-compaction.md)，集中职责不改变重试规则。完整助手会话历史与模型上下文视图独立保留，保留摘要额度、停止复核、版本保存及超限恢复不重复执行工具的契约。

Web 对话轮次运行职责集中管理提交接受、运行名额、停止、保存故障与真正完成后的名额释放，路由通过这一职责处理运行状态。保留单进程全局单轮执行、提交身份去重和公开 HTTP/SSE 行为；存储事务继续由本机存储负责。已发起调用须等待真实返回并记录事实，不能因停止或保存故障提前释放名额或伪报终态。

## 验证与阶段

按目录与导航、上下文维护、Web 运行状态的顺序实施，每步通过相关回归再继续。目录迁移验证真实 CLI/Web 启动、配置与静态资源定位、临时目录启动和现有数据读取；上下文整理验证压力与超限恢复的共用额度、完整历史、停止与重启；Web 整理验证并发提交、停止目标、保存失败与 SSE 续接。保留现有公开入口测试的行为覆盖，测试导入与替换目标随实现路径更新。

本记录确认设计取舍，实施规格已于 2026-10-13 发布为 [Issue #66](https://github.com/lll1024/Potato/issues/66)，尚未进入开发阶段；内部接口的职责与验证范围以该规格为准，不以本文作为实现或测试已通过的证明。
