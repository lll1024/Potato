# 默认获取旅行资料，仅按明确要求核实信息

旅行者反馈自动信息核实占用了较多旅行规划时间，联网工具的主要用途应是获取规划所需资料。2026-10-13 设计讨论确认：默认规划由旅行者自行核实信息，助手仅在旅行者明确要求时执行专项核实；助手仍按规划需要主动搜索攻略、玩法、地点和餐饮建议，并按需读取网页及查询地图。

## 已确认的边界

- 区分资料获取与信息核实，定义见根目录 `GLOSSARY.md`。普通规划不为证明每条信息可靠而追加官方查证、交叉核对或对旅行日期适用性的专项核实。获取地点坐标和交通路线等规划所需资料继续保留。
- “博物馆几点开门”等普通问询查询资料后直接回答；“帮我确认下周二是否开放”等明确要求查证真实性或适用性的问询进入专项核实，不仅依赖是否出现“核实”一词。
- 普通回答保留必要来源名称和实际取得的链接，简短提醒开放、预约等信息由旅行者出行前核实，不逐项生成来源身份、正文读取状态、查询时间、发布日期和适用范围的核实报告。未知信息不编造，取得资料不表述为已完成核实。
- 已取得资料显示闭馆日等明显冲突时直接指出并提出调整建议，不为消除冲突自动追加查证；资料互相矛盾时说明矛盾并交由旅行者核实。替换旅行者指定地点仍须先征求同意。
- 专项核实仅针对当前核实问题及明确续问生效，不把整个助手会话改为自动核实模式。后续普通规划恢复默认；修改旅行日期、恢复历史会话或回读资料不自动触发信息核实，仍按当前旅行要求获取规划所需资料并调整安排。
- 普通规划附上已有资料中取得的预订入口，不为补齐入口额外搜索。旅行者明确要求寻找预约或预订入口时再查询，但不因此自动核实全部政策、余票及操作流程。入口只能引用实际取得的信息，不构造链接或承诺有票、已预约或已预订。

## 与既有决策的关系

本方案替代 [ADR 0001](0001-domestic-planning-with-booking-entry.md) 中默认优先核实国内旅行信息、强制搜索官方渠道并读取正文后逐项查证，以及默认补齐预订入口的要求；明确要求核实时仍沿用专项核实所需的来源和日期条件检查。外部预约由旅行者自行完成、取得入口不等于有票或已预订、免费额度失败时降级等边界继续保留。

沿用 [ADR 0003](0003-relative-travel-dates.md) 的旅行日期解释与保留规则。[ADR 0005](0005-session-context-compaction.md) 中摘要和历史资料的核实边界遵循本记录：保留来源与已知状态，不让历史回读或日期变化隐含触发默认核实，也不把未核实资料升级为已核实事实。

## 取舍与阶段

选择减少默认查证及其模型与工具往返，接受普通旅行规划不提供已核实可执行性的保证；不承诺固定的耗时降幅。来源可供旅行者自行查证，已知冲突与缺失信息仍如实说明。

后续行为验收须覆盖普通规划、普通开放时间问询、明确专项核实及续问、核实后的普通规划、日期修改与历史恢复、资料冲突，以及默认附带入口与明确查找入口。判断查询目的与回答行为是否符合边界，不能仅以搜索或正文工具是否被调用判断是否执行了信息核实；这些工具仍可用于资料获取。耗时另行观察，不用固定降幅代替行为验收。
