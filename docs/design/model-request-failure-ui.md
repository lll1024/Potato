# 对话异常的紧凑展示

状态：用户于 2026-10-15 整体确认设计，随后调用 implement 进入实施阶段；以本文作为本次实现的设计依据。

## 已确认方向

- 以用户提供的 DeepSeek 失败界面截图为视觉依据：保留用户消息，在对应用户消息下方显示小型重试图标与一句短提示。
- 覆盖所有现有异常状态，包括模型请求失败、用户停止、查询或输出达到上限、本机服务退出或中断、地图查询暂停与存储故障。
- 去掉异常场景下聊天区的大段应用说明；无模型正文时，不再保留空的“旅行助手／应用说明”区域。
- 样式遵循参考图，短提示按真实原因区分，例如“连接超时”“服务暂时不可用”“额度不足”；未知原因显示“请求失败”。主动停止、达到上限与存储故障须使用各自的状态说明，不能统称为服务器不可用。
- 后台继续既有自动重试，期间只保留一行简短进度；最终结束为异常后，显示紧凑提示。
- 点击重试图标沿用现有恢复规则：仅最新符合条件的异常轮次可操作，用原需求创建新对话轮次，保留输入框草稿；执行或提交期间禁用，旧异常轮次保留提示。
- 聊天区移除“已有资料”等说明及展开入口，已有查询资料与详细错误通过本轮执行轨迹查看，保留本轮轨迹入口。
- 服务、地图及存储状态造成的重试限制沿用现有规则，紧凑展示不改变异常恢复能力。
- 查询或输出达到上限时，继续在聊天区展示已经收到的部分模型回答，并简短标注“回答不完整”；没有模型正文时不显示助手回复块。

## 现有约束

- 对话轮次可能包含多次模型请求，单次请求失败后可能仍在自动重试；最终失败与自动重试期间是不同状态。
- 按 ADR 0004，自动重试继续当前模型步骤，人工重新尝试则以原需求创建新对话轮次，可能再次查询。
- 现有人工重新尝试仅适用于最新异常轮次，受全局执行和服务状态约束，保留输入框草稿。
- 当前回答在轮次结束后完整显示；已有查询资料和执行轨迹可以保留供回看。

## 阶段边界

- 完整方案已由用户确认，用户随后调用 implement 明确授权开发；未单独发布实施 Issue。
- 本次不修改自动重试、持久化或模型上下文规则。聊天快照新增可选的模型错误分类码，从最终请求的既有错误记录读取，前端映射为短提示，不展示供应商原始错误。
- 本次未产生需要新增定义的领域术语；该展示调整可逆，不新增 ADR。

## 后续验证目标

- 各种异常均在对应用户消息下方呈现参考图中的紧凑状态，不再显示大段失败说明或空助手说明块。
- 提示与真实状态一致；重试不会重复提交或覆盖输入框草稿。
- 自动重试中只显示简短进度；异常结束后切换为紧凑提示，历史异常提示仍可回看。
- 达到输出或查询上限时保留部分回答，并标注不完整；没有模型正文时无空助手回复块。
- 已有资料及错误详情仍可追溯，桌面和窄屏均可操作，图标有可访问名称。
