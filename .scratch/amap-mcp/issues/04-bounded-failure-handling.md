# 04: 查询失败和预算耗尽时可靠结束

**What to build:** 一次旅行查询中部分工具失败、服务不可用或调用达到上限时，助手仍能说明已核实的信息和未完成部分，停止无效调用，并使本地运行可靠结束。

Blocked by: 01（跑通本地地点查询）

Status: ready-for-agent

- [ ] 将参数错误、未知工具、工具超时及 MCP 工具错误回传为与原调用对应的失败结果，不当成成功数据，也不丢失同一批调用中的其他成功结果。
- [ ] 部分查询失败时，最终回答保留已核实部分，将缺失部分标为“待核实”，不通过猜测补齐地点或交通事实。
- [ ] 为一次用户请求落实有限的工具超时、最大模型轮数和工具调用次数，集中定义初始值并写入运行说明；轮数和调用次数是整次请求的预算。
- [ ] 即使模型持续请求工具，预算达到上限后也不再发起超额调用；返回明确的终止说明及可用信息，正确处理同一批调用中剩余的未执行请求。
- [ ] 鉴权失败、额度耗尽或连接不可用时给出可操作的说明，并停止反复调用同一工具；普通失败不触发无限重试。
- [ ] 失败或预算终止后保留合法的消息与工具结果对应关系，后续用户请求可以继续使用当前对话；不可恢复的连接错误明确结束运行。
- [ ] 正常退出、中断和异常均释放连接；错误、日志和最终回答不泄露 Key 或带凭据的连接地址。
- [ ] 通过可控模型与工具故障测试混合成功失败、未知工具、参数错误、超时、鉴权失败和预算耗尽，观察实际调用次数、工具错误状态与终止结果。
- [ ] 不依赖路线比较或餐饮推荐功能即可验证上述行为；这些功能随后复用同一套错误与预算处理。

覆盖规格用户故事：23、24、25、26、30。
