# 04: 查询失败和预算耗尽时可靠结束

**What to build:** 一次旅行查询中部分工具失败、服务不可用或调用达到上限时，助手仍能说明已核实的信息和未完成部分，停止无效调用，并使本地运行可靠结束。

Blocked by: 01（跑通本地地点查询）

Status: ready-for-agent

- [x] 将参数错误、未知工具、工具超时及 MCP 工具错误回传为与原调用对应的失败结果，不当成成功数据，也不丢失同一批调用中的其他成功结果。
- [x] 部分查询失败时，最终回答保留已核实部分，将缺失部分标为“待核实”，不通过猜测补齐地点或交通事实。
- [x] 为一次用户请求落实有限的工具超时、最大模型轮数和工具调用次数，集中定义初始值并写入运行说明；轮数和调用次数是整次请求的预算。
- [x] 即使模型持续请求工具，预算达到上限后也不再发起超额调用；返回明确的终止说明及可用信息，正确处理同一批调用中剩余的未执行请求。
- [x] 鉴权失败、额度耗尽或连接不可用时给出可操作的说明，并停止反复调用同一工具；普通失败不触发无限重试。
- [x] 失败或预算终止后保留合法的消息与工具结果对应关系，后续用户请求可以继续使用当前对话；不可恢复的连接错误明确结束运行。
- [x] 正常退出、中断和异常均释放连接；错误、日志和最终回答不泄露 Key 或带凭据的连接地址。
- [x] 通过可控模型与工具故障测试混合成功失败、未知工具、参数错误、超时、鉴权失败和预算耗尽，观察实际调用次数、工具错误状态与终止结果。
- [x] 不依赖路线比较或餐饮推荐功能即可验证上述行为；这些功能随后复用同一套错误与预算处理。

覆盖规格用户故事：23、24、25、26、30。

## Comments

### 2026-10-08 实施与验证记录

- `limits.py` 集中定义单次工具超时 30 秒、每次用户请求 12 轮模型及 24 次工具调用；预算跨批累计，下一次用户请求重置。三日地点查询模拟以 9 个地点的检索及详情共 18 次工具调用、7 轮模型请求验证默认容量，未提前实现多日旅行行程功能。
- 保留混合成功失败结果及原工具调用对应关系；识别高德自身失败状态，即使 MCP 未标记 `is_error`。鉴权、额度和服务故障停止当前查询并禁用当前连接上的进一步地图调用；不可恢复断连结束 CLI。参数错误、超时与普通 MCP 失败不丢失同批其他成功结果。
- 预算及故障终止时直接返回本次已查询成功的原始信息、失败和未执行查询条件以及“待核实”说明，不超额调用模型总结。对话历史保持合法，后续请求可继续使用；模型服务错误也保留已查结果。
- HTTP 集成测试复现 SDK 高层工具调用的隐藏重试，通过单次会话调用确保实际工具请求不越过预算。验证正常退出、EOF、中断、取消、异常及断连时释放连接；入口支持 SDK 异常组，并隐藏网络日志。凭据原文、URL 编码形式和带凭据 URL 在声明、历史及最终回答中脱敏。
- 38 项全量自动测试通过；类型检查 0 错误、0 警告；差异格式检查通过。测试使用可控模型、工具返回及官方 SDK 的本地 HTTP/进程内服务，不消耗真实模型或高德额度。
- 规格审查复现了 SDK 丢失普通 HTTP 401/429/503 状态、后台网络异常导致整批结果丢失的问题。新增薄的 HTTP 适配层保留故障类型和原请求 ID；补充真实 SDK 的 HTTP 状态、连接建立失败、JSON/SSE 读取中断及正常 SSE 测试，确保保留首个成功结果、补齐故障及未执行结果并可靠终止。
- 编码准则审查发现一处重复 HTTP 状态分类，已提取共享函数；规格审查的两项故障缺陷均已修复。两轴复审未解决发现均为 0 项；最终 38 项全量测试及类型、差异检查通过。
- 本任务未执行真实高德及真实模型故障验收；可控模型回复不证明真实模型必然遵循部分失败回答规则。按 README 人工核对真实回答，不将模拟结果报告为实连通过。
