# 03: 按区域和偏好推荐餐饮

**What to build:** 用户给定区域或地点，并按需要提供餐饮偏好，助手查询餐饮候选地点、给出可定位的推荐和理由，区分查询事实、建议与无法核实的信息。

Blocked by: 01（跑通本地地点查询）

Status: ready-for-agent

- [x] 接入餐饮关键词和周边检索所需能力，沿用实际工具发现与开放清单，不引入额外餐饮评价数据源。
- [x] 给定区域或地点，查询并返回具有名称和可用位置或地址信息的餐饮候选；推荐依据实际返回的信息与本次对话中的偏好。
- [x] 对话中已经给出的口味等偏好直接复用；次要偏好未给出时可采用明确说明的假设，允许用户通过对话调整，不要求长期记忆模块。
- [x] 推荐理由能够对应查询事实或用户条件；不编造未获取的评分、口碑、价格或营业时间，缺失信息明确说明。
- [x] 没有合适候选或查询未返回餐饮地点时说明结果，不能用虚构地点填充推荐。
- [x] 通过可控模型与地图返回验证区域和周边检索参数、餐饮结果向模型的传递、已有偏好的复用以及空结果处理。
- [x] 人工验收一次区域餐饮推荐和一次偏好调整，检查地点可定位、推荐理由有依据；实连不可用时明确记录验证限制。
