# 旅行助手接入高德 MCP

Status: ready-for-agent

## 问题陈述

用户希望通过对话查询旅行地点、比较交通路线、选择餐饮，并按需要安排多日旅行行程。现有助手已经具备模型请求工具、执行工具、回传结果的基础循环，但工具仅用于编程和文件操作，尚未连接地图服务，无法据此提供经过查询的地点和交通信息。

第一版先在本地命令行运行，面向小范围多人试用；未来可能迁到网页入口并添加记忆模块。当前接入应完成旅行能力所需的工具闭环，并使核心循环可以被后续入口复用。

## 解决方案

将助手转换为旅行助手，通过高德官方 MCP 查询地点、天气与交通信息。用户可以请求地点查询、交通路线比较、餐饮推荐及一天或多天的旅行行程，并在同一次对话中继续调整安排。

关键条件缺失时先澄清；次要偏好可采用明确说明的假设。查询失败时保留已核实的信息，将缺失部分标为“待核实”。第一版只使用当前对话的信息，不保存旅行行程，也不开放编程工具。

## 实施决策

### 接入与模块职责

- 保留现有模型与工具调用循环，通过一个薄的高德 MCP 适配模块接入地图服务。
- 使用高德官方托管的 Streamable HTTP 服务。凭据使用高德“Web 服务”类型 Key，并通过运行环境配置。
- 使用官方 MCP Python SDK 管理协议与连接生命周期，使用异步模型客户端，将模型请求与工具调用放在同一异步运行入口内。
- 实施时锁定 SDK 版本，并验证与高德服务的实际兼容性；不根据新版文档假定高德已经支持特定协议版本。
- 运行入口负责读取配置、建立和关闭连接、维护本次对话历史及处理终端输入输出。
- 核心循环接收当前会话消息、模型客户端和地图工具适配对象，执行一次用户请求并返回最终回答。核心循环不直接依赖终端输入或打印。
- 地图适配模块负责工具发现、开放工具筛选、模型工具声明转换、调用转发及结果转换，不负责旅行行程或用户偏好的存储。
- 替换编程助手系统提示词，移除现有 shell、文件读取、文件写入、文件编辑和文件查找工具。
- 提供最小依赖声明、环境配置示例和本地运行说明。配置示例使用占位符，保留现有模型与兼容服务地址配置能力。

### 工具契约

- 启动时发现工具；开放能力限于地点检索与详情、地理编码、交通路线、天气及距离查询。工具名称及参数结构以实际发现结果为准，实施时建立明确的开放清单。
- 将开放工具的名称、描述和输入参数结构转换为模型支持的工具声明，不手写与实际服务不一致的参数定义。
- 模型只能调用开放清单中的工具；未开放或未知工具返回明确错误，不转发至高德。
- 每个模型工具调用都得到与原调用对应的结果，包括失败结果；同一批调用部分失败时保留其他调用的成功结果。
- 将 MCP 文本和结构化数据转换为模型可用的工具结果，保留地点标识、坐标、耗时和距离等旅行所需信息及工具错误状态，不把 SDK 结果对象直接当成字符串。
- MCP 查询结果是事实来源；活动选择、先后顺序和餐饮推荐理由由助手结合用户条件组织。

### 对话与规划行为

- 复用当前对话中明确提供的日期、天数、城市、起终点和偏好，不重复询问已有条件。
- 缺失会影响查询或整体旅行行程的条件时先澄清；次要偏好可采用明确说明的假设，再根据反馈调整。具体追问顺序由实施者按请求场景安排。
- 查询交通路线前明确起终点；对无法区分的同名地点结合城市、地址等信息先澄清。
- 多日旅行行程按日期或第几天组织，给出活动顺序、餐饮建议及地点之间的交通安排。地点与交通事实应来自查询结果。
- 餐饮推荐依据实际获取的地点信息及用户已提供的偏好，不承诺未查询到的评分、口碑、价格或营业时间。
- 天气建议只覆盖实际返回的预报范围；查询不到的未来日期明确说明，仍可继续规划。
- 当前对话可以修改旅行行程，退出后不保存对话、行程或偏好。
- 后续记忆模块可以提供偏好供上下文使用；本次不提前实现记忆模块、持久化或专用记忆接口。

### 失败、预算与退出

- 对工具调用设置超时，并对一次用户请求设置最大模型轮数和工具调用次数。三项预算使用集中定义的有限值；实施者根据三日旅行行程验证确定初始默认值并写入运行说明。
- 调用上限覆盖整次用户请求，不被单次模型输出 token 上限替代。预算耗尽后停止继续调用，并明确返回已获取的信息和未完成部分。
- 普通工具错误转换为错误结果供模型处理；不把失败内容当成成功数据。
- 查询失败时提供已核实的部分，将缺失信息标为“待核实”；关键地点无法确定时先澄清，天气缺失可以继续规划。
- 鉴权失败、额度耗尽或连接不可用时明确说明问题，不反复调用同一工具尝试恢复。
- 配置缺失或启动连接失败时报告可操作的说明，不进入没有可用地图工具却声称已完成查询的模式。
- 日志和错误内容对 Key 脱敏，尤其避免输出带凭据的连接地址。凭据不进入工具声明或模型上下文。
- 正常退出、用户中断和异常结束时关闭运行期间创建的客户端连接。

## 测试决策

### 主要验证边界

以核心循环的“单次用户请求到最终结果”接口为主要测试边界，复用现有循环接收对话历史的设计。使用可控的模型回复和地图工具返回，观察最终回答、对话中回传的工具结果、实际工具调用及终止行为。

只验证外部行为，不断言私有函数、内部组织方式、工具调用的无关顺序或真实模型的固定措辞。地图适配模块只有无法从该边界覆盖的声明与结果转换行为才补充直接测试。

仓库当前没有测试或测试框架先例。使用轻量的 Python 测试方案，不依赖真实高德 Key 或模型费用运行自动检查。

### 自动验证

1. 工具发现后，仅向模型提供开放清单中的工具及其实际参数结构。
2. 模型发起地图调用时，名称和参数正确转发，文本与结构化结果关联回原调用。
3. 同一批工具调用中，一个失败不会丢失其他成功结果；失败状态可被模型识别。
4. 未知工具、参数错误和工具超时返回明确错误，不导致循环失去对应的工具结果。
5. 模型重复请求工具时，最大轮数或调用次数触发后实际停止，不越过预算继续调用。
6. 对话历史由调用方提供，不在独立会话之间共享；核心循环无需终端输入输出即可执行。
7. 凭据不会出现在工具声明、返回错误和日志中，连接在退出或异常时释放。

### 实连与人工验收

| 场景 | 输入或条件 | 验收结果 |
| --- | --- | --- |
| 接入冒烟验证 | 有效配置，发现工具并执行一次地点查询 | 确认实际协议兼容、工具参数与返回格式；查询返回真实地点 |
| 地点与路线比较 | 给定城市及明确起终点，比较适用交通方式 | 地点匹配正确，耗时和距离有查询依据，说明比较结论 |
| 餐饮推荐 | 给定区域及偏好 | 返回可定位的候选地点，推荐理由对应实际信息，不编造口碑 |
| 多日旅行行程 | 给定日期、三天时长、城市与偏好 | 按天安排活动和餐饮，结合查到的地点及交通信息，不把单条交通路线当成整次旅行 |
| 条件不足 | 天数缺失或目的地存在同名歧义 | 先澄清关键条件，复用已有信息，不重复提问 |
| 对话修改 | 在已生成行程后替换某个地点 | 基于当前对话调整受影响的安排和交通信息 |
| 部分失败 | 路线或天气查询失败 | 保留已核实部分，标明缺失；关键地点不明时澄清，不编造结果 |
| 本地使用边界 | 独立运行及退出后重启 | 没有编程工具，不读取其他运行的对话，不保存行程 |

实连验证先进行低成本冒烟检查，再验证用户场景。缺少可用凭据或服务不可用时，记录未完成的验证，不将模拟结果报告为实连通过。

## 不在范围内

- 网页界面、地图可视化、聊天机器人入口和公开部署。
- 面向公开用户的账号体系、计费、多租户服务及并发运行治理。
- 旅行行程保存、跨次运行恢复、长期记忆和偏好存储。
- shell 执行和本地文件操作等编程助手能力。
- 自动订票、预订餐厅、下单打车或其他交易行为。
- 独立的餐饮评价平台、额外互联网数据源，以及超出高德实际返回信息的口碑或营业保证。
- 另行实现 MCP 服务端、通用插件框架或重新构建 Agent 框架。

## 补充说明

- 本规格由已完成的设计访谈整理，用户已确认不保存行程、不需要编程工具，并接受信息澄清及部分失败处理原则，其余接入细节由实施者安排。
- 本地命令行试用与以后网页使用的区别主要在入口、用户会话和并发管理。此次将终端交互与核心循环分开，为迁移保留复用边界。
- 高德精确工具清单、参数结构、实际协议兼容性及账号配额仍需实施时确认，不构成新增产品需求。
- 当前仅完成规格，接入代码及实连验证尚未完成。
