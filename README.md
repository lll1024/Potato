# 旅行助手

支持本地地点查询、交通路线比较、餐饮推荐以及一天或多天的旅行行程：助手通过高德 MCP 核实地点、交通、餐饮和可用天气，按日期或第几天组织活动，并支持当前对话中的后续调整。开放地点检索与详情、周边检索、地理编码、逆地理编码、距离、天气及步行、骑行、驾车、公交路线工具。

## 本地运行

使用 Python 3.11 或更高版本，建议在项目虚拟环境中运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

参考 `.env.example` 配置项目根目录的 `.env`，保留已有有效配置，不覆盖真实凭据：

- `MODEL_ID`：所用模型服务支持的模型名称。
- `ANTHROPIC_API_KEY`：模型服务的 API Key；官方服务也可使用已有的 `ANTHROPIC_AUTH_TOKEN` 配置。
- `ANTHROPIC_BASE_URL`：使用 Anthropic Messages 兼容服务时填写；官方服务留空。兼容服务沿用原有逻辑，优先使用 API Key。
- `AMAP_MAPS_API_KEY`：高德“Web 服务”类型 Key。

高德凭据需要在[高德开放平台](https://lbs.amap.com/api/mcp-server/create-project-and-key)创建。连接使用[官方 Streamable HTTP 服务](https://lbs.amap.com/api/mcp-server/gettingstarted)，不使用已下线的 SSE 服务。

```sh
python agent.py
```

示例输入：`查询杭州的西湖，列出查到的地点和地址`。同一进程中的后续问题可以复用前面的条件，输入 `q`、`exit` 或空行退出。退出后不保存对话或旅行行程，不提供 shell 或文件操作工具。

交通路线示例：`在杭州，从杭州东站到浙江省杭州市上城区龙翔桥地铁站，比较公交和驾车。`
助手会先核对起终点；同名地点无法区分时列出名称和地址供确认，缺少起点时先追问。后续可输入 `再看看步行` 复用已确定的地点。
仅比较实际查询成功的交通方式，未返回的耗时或费用标为待核实；驾车结果不代表已核实的打车时间或价格，直线距离也不代表交通路线距离。

餐饮推荐示例：`在杭州上城区湖滨商圈推荐2家面馆。我喜欢清淡、不吃辣，预算暂不限。`
后续可输入 `改成粤菜，范围换成龙翔桥周边2公里，其他条件沿用` 调整偏好，并复用已提供的城市和口味。
区域检索会结合区域关键词并核对候选地址；周边检索先确认中心地点坐标。搜索半径等次要条件未提供时会说明假设。
每个推荐包含查询所得的名称及可用地址或坐标，理由区分地图事实和结合偏好的建议。关键词、店名或餐饮类型不能保证菜品口味；未获取的评分、口碑、价格、菜单及营业时间会标为待核实。
没有合适的餐饮候选时说明查询结果，可调整范围或条件后继续；仅使用高德已开放工具，不引入其他评价数据源，不保存偏好。

三日旅行示例：`请安排2026年10月9日起三天的杭州旅行，每天10点从首个活动地点开始，无需住宿往返或外地进出。每天两个活动，途中推荐一家午餐餐馆，清淡不辣，预算暂不限，公交优先，短途可步行。请结合天气，按日期列出活动、餐饮与各地点之间的交通。`
后续可输入 `把第2天的第一个地点换成灵隐寺，当天午餐改为素食，其他条件不变`；助手复用日期、城市及未修改的偏好，核实新地点并重查受影响的餐饮和前后交通，其余日期沿用。
一天示例：`2026年11月1日在杭州玩一天，10点从太子湾公园开始，下午去中国丝绸博物馆，途中推荐一家清淡不辣的午餐餐馆，公交优先，无需住宿往返。`
日期、天数、城市等影响整体安排的条件缺失或矛盾时先澄清；给定日期范围可推导天数。若明确只要不指定日期的草案，可按第几天安排并说明没有对应日期的天气依据。节奏、搜索半径等次要条件采用说明过的假设；需要从酒店等地点出发时必须提供并确认起点，不能猜测。
活动顺序、游览时长和建议时段属于安排建议；地点、餐饮和交通事实以查询为准。活动与午餐之间的每段交通单独查询，未查到的衔接标为待核实；景点直达路线不能替代经过餐馆的路线。门票、预约、开放时间、餐饮口味及营业信息没有返回时仍待核实，不补充常识中的票种或购票流程；常规开放时段只能用于检查计划是否冲突，不能保证未来当日开放。用户指定地点无法确定时先澄清，不能自行用附近地点替换。
天气工具 `maps_weather` 只接收实际声明中的城市或 adcode；预报覆盖日期以返回结果为准，不传入自定义日期、不外推天气。超出预报范围、工具不可用或查询失败时明确标为“天气待核实”，仍可基于已核实地点提供有说明的旅行行程。

工具查询失败时会回传对应调用的错误，保留同批其他成功结果。未知工具不会转发；参数错误、超时及 MCP 错误不作为成功数据。部分失败时保留已核实信息，缺失的地点、交通及其他信息标为“待核实”。普通失败没有自动重试。

预算集中定义在 `limits.py`：每次用户请求最多 80 次模型请求、64 次工具调用，单次地图调用超时 30 秒。模型请求次数和工具调用次数跨同一次请求的所有批次累计，下次用户请求重新计数；修改预算后需重启运行中的服务才能生效；模型请求另设 60 秒超时且不自动重试。地图调用使用 SDK 的单次会话接口，避免高层客户端隐藏的重新发现与重试突破调用预算。依据当前个人账号的每项服务 3 QPS 限制，地图适配层统一将请求发出间隔设为至少 0.4 秒（`MAP_CALL_INTERVAL`），跨当前对话的后续请求保留间隔；限速等待不占用单次网络调用的 30 秒超时。该串行限速仅管理当前运行，多进程共用同一账号仍共享服务额度，遇到限流时停止查询且不自动重试。配额依据见[高德基础服务说明](https://lbs.amap.com/pages/base_service_price)。`amap_http.py` 在 HTTP 边界保留鉴权、限流、服务故障和网络断连类型，转换为对应请求的协议错误，避免 SDK 丢失 HTTP 状态或后台异常取消整批结果；JSON 与 SSE 读取中断均按此处理。
预算或服务故障终止时，不再调用模型生成总结，应用只提供简短的未完成说明。网页将已保存且成功的查询资料整理为默认折叠的摘要；地点候选、常规开放时间及天气实际覆盖日期均说明适用限制，不补造缺失字段，无法整理的返回提供处理记录入口。完整原始返回、参数和诊断信息继续保留在执行轨迹，旧异常会话也采用同样呈现，不改写原始历史。同批未执行请求仍回传对应结果，合法的消息与工具结果关系继续保留。

最近异常轮次提供“重新尝试”：在同一助手会话以原需求创建新对话轮次，保留失败记录并沿用现有可用协议上下文与预算；中断轮次仍整体排除后续上下文。操作不覆盖草稿，可能再次查询，不是断点恢复。全局忙、停止中、待核对提交、本机不可用或地图暂停时禁用新重试；提交结果不明时核对或安全重试原提交，沿用原提交身份。刷新、切换、重开及服务恢复均不会自动执行。页面“本机可接收输入”只说明本机输入能力，不代表外部服务健康。实现及验证边界见[异常结束体验验收](docs/acceptance/exception-experience.md)。

鉴权失败时检查有效的 Web 服务 Key、服务权限及白名单；额度或限流问题请检查高德控制台，恢复后重启。此类故障会停止本次查询，并在当前运行中禁用进一步地图请求；仍可继续讨论已有信息。不可恢复的地图连接错误会明确结束本地运行，请检查网络和服务状态后重新运行。模型服务错误会保留已查结果并停止本次请求，修复模型配置、网络或额度后可在当前对话继续。错误分类结合 HTTP 状态及[高德官方错误码](https://lbs.amap.com/api/webservice/guide/tools/info)。
正常退出、EOF、中断、取消和异常都会退出客户端上下文并释放连接。入口隐藏底层网络日志；工具声明、对话历史、结果及最终回答会隐藏已配置凭据和带凭据的连接地址。

## 本机页面

页面复用上面的 Python 环境和 `.env` 配置。首次安装或修改前端后，使用 Node.js 20.19+ 或 22.12+ 构建静态页面：

```sh
npm ci --prefix frontend
npm run build --prefix frontend
```

日常只启动一个 Python 服务：

```sh
source .venv/bin/activate
python web.py
```

打开 `http://127.0.0.1:8000`，输入需求并发送。左侧为新建入口和历史会话，主区域通过“对话／轨迹”切换，底部输入区保持可见；手机可收起会话导航。页面显示完整输入、最终回答来源及实际轮次状态，不逐字输出。回答支持 Markdown 标题、列表、表格和代码，原始内容仍可在轨迹中读取。新建只展示空白对话，发送被接受后才保存会话。历史可分页回看、续聊、重命名和确认删除；页面内切换会话保留各自草稿。执行轨迹按轮次、模型请求和工具调用关联，提供真实边界时间线、完整详情、摘要／全文搜索以及长载荷分段和完整复制。查看历史、搜索、详情与复制不发起外部调用。阅读旧内容或展开详情会暂停跟随，可点击“回到最新”主动恢复；窄屏使用行内详情。

页面的“旅行者偏好”入口集中管理本机旅行者的稳定饮食、活动兴趣、交通和住宿喜好。仅处理功能启用后新提交的明确本人表达，不扫描旧聊天；游玩节奏、当前精力、单次旅行日期、预算、具体酒店和同行人要求不会成为长期偏好。一个数据目录对应一位旅行者，偏好不自动过期，独立 CLI 不读写这些记忆。

后台从会话最后一轮实际结束后连续闲置满 **3600 秒**开始具备提取资格，生产服务每 30 秒检查一次；新输入重新计时，执行中或停止中的会话跳过。打开页面、阅读历史和编辑未发送草稿不影响计时，关闭浏览器后服务仍继续处理。旅行回答不等待提取，紧接着新建会话时可能尚未使用刚表达的偏好；自动保存没有弹窗或逐次通知，可在管理页查看真实结果及失败状态。

当前明确要求优先于已保存偏好。“这次可以吃一点辣”只影响当前会话，“我现在喜欢吃辣了，以后也这样推荐”才改变长期记录；无法区分时保留原值，留待之后讨论相关需求时澄清。管理页可修改或删除条目，版本冲突需要重新读取后核对；管理结果持久保存，迟到的旧提取结果不能撤销操作。管理护栏以条目为单位：管理前已接收的相关旧表达不能恢复该条目，同类别的独立喜好仍可保存；请求期间发生管理操作时，后台按新的记录级撤销依据重新提取。以后新表达仍可保存。停止本轮同时取消该轮尚未提交的提取资格，已经保存的偏好保留。

聊天与偏好需要分别删除：删除聊天保留已保存偏好，删除偏好不清除原聊天，保留的会话仍可按原文续聊。删除后不会从旧聊天或此前未提交的提取结果自动恢复；以后重新提交明确表达仍可重新保存。服务重启会恢复有效待处理输入并重新检查闲置条件，不重放旅行回答或地图调用；提取失败采用有限重试，仍失败则显示未保存，已有偏好和普通回答保持可用。存储故障继续按原有保护停止接受输入，不视为普通模型失败。

服务仅监听本机 `127.0.0.1`，单进程、单工作进程，无日常热重载。`--port 8001` 可以修改端口；`--data-dir /你的路径/旅行记录` 指定 SQLite 目录，默认 `.travel-data`。同一数据目录只能有一个执行服务，第二实例会拒绝启动；数据库版本不支持时明确拒绝。SQLite、伴随文件和默认数据目录不提交 Git，重启不会清空已保存记录。不要把自定义数据目录提交到版本控制。

接受输入时事务保存用户输入、稳定会话／轮次身份及接受事件，然后启动后台任务；保存失败不会调用外部服务。Web 全局最多运行一轮，另一次发送返回忙且不排队。关闭、刷新页面不取消任务，最终结果仍保存；正常退出服务会等待已进入的调用返回，在边界阻止后续请求，再释放共享客户端。页面的“停止”针对当前轮次：未进入 SDK 的后续调用不再发起，已进入调用仍等待真实返回，正在停止仍占名额。自然最终回答、真实模型失败和输出上限先到时按真实终局保存，重复或晚到停止不改写记录。

正常 Ctrl+C 退出服务会完成上述边界停止与客户端释放。强制杀进程或断电不会被描述为远端撤销；下一次启动仅保留已成功保存的事实，未完成请求／工具显示“中断，结果未知”，不补结束时间、耗时或 usage。整个中断轮次排除于后续模型上下文，既有完整轮次仍可继续；重新提交问题是新轮次，不自动重放。存储故障时页面明确提示未保存事实并停止接受新输入，检查磁盘、权限和数据库后重启核对，不把未落盘返回当作已保存结果。

页面、通知和 SQLite 不接收配置凭据；输入与模型、地图结果在保存和展示前脱敏，包括已知凭据、编码形式、凭据字段和带凭据 URL。标题取首条输入的前 40 个字符。失败或预算终止保留应用说明来源，普通工具错误后正常回答显示“完成，含工具错误”。

历史保存为数据目录中的 `travel.sqlite3` 及 SQLite 伴随文件，重启保留；删除会话会删除其消息、上下文、载荷与轨迹，提交去重仅留下已处理身份，不能重建已删除会话。删除运行中或正在停止的会话会被拒绝。保留数据目录即可继续使用本机历史，本版没有备份、导出或自动清理；更改数据目录会打开另一份记录。

Web 的会话共用模型／HTTP／MCP 客户端以及一个地图适配实例，地图限速和暂停状态在该服务进程内共享。地图鉴权、额度／限流、服务或连接故障会暂停查询，切换、新建或删除会话不会解除。检查 Key、权限、白名单、额度、网络或服务状态并修复后，退出并重启 `python web.py`，再按真实返回判断是否恢复；重启不代表额度重置。普通参数错误、查无结果或单次超时不等于共享暂停，不自动重试。不可恢复的地图连接错误保存可可靠保存的事实并退出服务、释放连接。独立的 `python agent.py` 和 `python agent.py --check-amap` 保留原行为，与 Web 不共享执行名额、进程内限速或暂停；同时使用同一账号会叠加外部调用，不能视为账号级限速。

开发时可另开 `npm run dev --prefix frontend`，Vite 将 `/api` 代理到本机 8000 端口；日常静态页面由 Python 同源提供，无需 Node 开发服务。

## 验证

首版页面的验收矩阵、复现方式和实际限制见 [本机页面验收记录](docs/acceptance/local-web.md)。自动测试在模型服务和地图服务边界使用可控返回，不消耗真实调用额度：

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
pyright --pythonpath .venv/bin/python agent.py amap_mcp.py amap_http.py limits.py web.py store.py preferences.py
```

前端重设计的排版、安全与时间线检查，以及生产构建：

```sh
npm test --prefix frontend
npm run build --prefix frontend
```

本轮验证范围见 [前端重设计验收](docs/acceptance/frontend-redesign.md)，设计规则见 [DESIGN.md](DESIGN.md)。

仅验证高德连接、实际工具发现和一次地点查询，不调用模型：

```sh
python agent.py --check-amap
```

该检查查询“杭州的西湖”，会消耗一次实际高德地点查询。缺少高德 Key 或服务不可用时不能视为实连通过。它不替代完整模型到地图再到回答的人工验收。

失败与预算测试覆盖混合成功失败、参数错误、未知工具、MCP 与 HTTP 超时、鉴权、额度、断连、预算跨轮累计及后续对话；SDK 集成测试检查实际 HTTP 工具请求不被隐藏重试、断连停止运行以及退出时释放连接。三日组合测试包含每天三个活动的检索与详情、一次餐饮查询、从已知酒店出发的四段交通，以及一次天气查询，共 34 次工具调用，批量查询需要 13 次模型请求，逐条查询需要 35 次模型请求，均可获得最终回答。2026-10-09 本地三亚请求以每次模型请求调用一个工具的方式查询，在 20 次模型请求、20 次成功工具调用后触发程序预算，因此将模型请求上限提高至 80 次，允许地图预算内的逐条查询并留出最终回答余量。实连校准时，三日请求曾累计请求 52 次工具而触发 48 次上限，因此保留 64 次工具调用上限，并要求优先完成必要的餐饮和交通衔接，减少穷举候选及冗余距离查询；仍不保证任意复杂旅行请求都能完成。行程自动测试还验证替换地点后的当前对话传递、新餐饮与前后交通、一天场景、预报范围及天气或路线失败状态。可控模型的预设文本不证明真实模型能正确规划或澄清；真实回答仍须另行核对查询依据及“待核实”标注。

交通路线人工验收可在同一次 CLI 对话中依次检查：

- 输入上述杭州东站到龙翔桥的示例，核对地点、各方式的耗时和距离是否对应工具返回，并检查比较建议。
- 输入 `再看看步行`，检查是否复用前面的城市和起终点。
- 输入 `在杭州，从肯德基到龙翔桥地铁站，比较公交和驾车`，检查是否先澄清具体分店。
- 输入 `在杭州，去龙翔桥地铁站怎么走`，检查是否先追问起点。

路线及地理编码参数来自启动时实际发现的声明；公交须同时提供 `city` 和 `cityd`，坐标格式为 `经度,纬度`。自动测试使用 2026-10-08 实际发现的工具契约及可控模型、地图返回，验证参数转发和结果回传；模型能否正确选择地点、追问和组织比较，需通过实连验收另行检查。

餐饮人工验收可在同一次 CLI 对话中输入上述区域推荐示例，再输入偏好调整示例，检查：

- 推荐门店的名称、地址或坐标对应实际工具返回，且符合指定区域或周边范围。
- 原有口味条件得到复用，改动后的菜系和半径用于重新查询；周边坐标来自已确认地点，不能猜测。
- 推荐理由对应已返回信息或用户条件，缺失的口味、口碑、价格及营业信息明确标注。

餐饮自动测试使用同日实连发现的关键词、周边及详情工具契约；周边工具的 `location` 为 `经度,纬度`，`radius` 为以米计的字符串。测试验证区域和周边参数、文本与结构化餐饮结果、两轮对话历史以及空结果或非餐饮结果向模型的传递。可控模型回复不证明真实模型必然遵循推荐规则，实连与回答核对须另行完成。

多日旅行行程人工验收：

- 在当前对话输入完整三日示例，核对三天日期、活动地点及午餐地址；逐段检查“活动→餐馆→下一活动”的交通是否对应查询两端及返回耗时、距离。
- 替换第2天首站并调整午餐偏好，核对原日期、城市和其余条件得到复用，新地点、餐饮及前后交通已重查，第1、3天保持原安排。
- 用一天示例检查只组织一天；超出天气返回日期时明确标注天气待核实，仍给出有查询依据的其他安排。
- 日期或天数缺失、关键地点存在同名歧义时先澄清；路线或天气部分失败时保留成功信息，并逐项标注待核实。
- 可控快速返回测试检查连续地图请求遵守每秒最多三次，预算结束、限流终止及独立会话/退出行为由核心循环和 SDK 测试覆盖。
